# Work Summary - 2026-05-01 to 2026-05-02

## Executive Summary

Over the last work cycle we stabilized two previously conflicting paths:

1. Broadcast Alt SS-TWR positioning for 3 Tags at 10 Hz/tag.
2. AutoPos inter-anchor Matrix sweep using traditional anchor-to-anchor SS-TWR.

The important architecture decision was to stop sharing the broadcast responder
timing/matching path with Matrix sweep. Broadcast responder remains optimized
for Tag poll handling, while Matrix now uses slow, traditional unicast SS-TWR
because inter-anchor sweep has no motion-error constraint.

Final pipeline validation after a full manual power cycle passed:

```text

Responder handoff: ready=8/8
Broadcast positioning: 600s, 3 Tags, positions_all=18002, tf_all=0
Per Tag rate: ~10 Hz each
```

## Why AutoPos Broke

The original SS-TWR architecture used nearly the same low-level responder path
for both:

- Tag ranging responder
- Matrix inter-anchor responder

The only meaningful difference used to be whether Tag polls were allowed.

After broadcast Alt SS-TWR, responder mode became a different protocol path:

- broadcast destination `0xffff`
- mask/rank scheduling
- guard + response spacing
- Tag-oriented frame matching
- no-sleep hot-path timing

Matrix sweep, however, still needs simple anchor-to-anchor unicast SS-TWR:

```text
Master Anchor -> peer Anchor unicast poll
peer Anchor -> unicast response
```

Because Matrix had inherited parts of the broadcast responder behavior, peers
stopped responding correctly to Matrix polls. Earlier symptoms included:

```text
SW-A/B/D/G/H rows containing zeros
listener saw Matrix poll frames on air
listener did not see corresponding peer responses
apply worker sometimes got stuck around converge / handoff
```

## AutoPos Repair

The fix was to split Matrix matching and response timing from broadcast Tag
responder logic.

Changed files:

```text
src/ss_twr_resp.c
src/ss_twr_anchor_init.c
src/uwb_ss_twr_shared.c
```

Important behavior:

```text
Responder mode:
  allow_tag_polls=1
  accepts Tag/broadcast Alt SS-TWR poll
  uses broadcast mask/rank/guard/spacing logic

Matrix mode:
  allow_tag_polls=0
  accepts only anchor-origin unicast poll
  uses traditional SS-TWR response delay
  ignores Tag/broadcast poll scheduling
```

a17 marker:

```text
alt-bcast-a17-matrixslow-g1200-r1000
```

a17 Matrix timing:

```text
APP_ANCHOR_MATRIX_RESP_DELAY_UUS=1200
APP_ANCHOR_MATRIX_RESP_RX_TIMEOUT_UUS=3500
```

The 1200 us Matrix response delay is intentionally conservative. Matrix does
not need sub-millisecond sweep timing; reliability matters more here.

## Current Status

The system now has a validated mode sequence:

```text
Power cycle
  -> AutoPos Matrix 100-set sweep
  -> switch A-H to responder
  -> 600s broadcast positioning
```

This sequence passed without firmware changes during the validation run.

## Remaining Observations

1. Anchor H appears much less often in broadcast position anchor sets than A-G.
   This did not prevent stable 10 Hz/tag output, but it should be investigated.

2. Matrix low-quality warnings are localized:

```text
G round: C/H low quality in 100-set run
D/E/G pair warnings in smaller probes
```

These look like RF, placement, antenna orientation, supply, or layout issues
rather than protocol failures.

3. Anchor layout is still stale. RMS values should not be treated as final
quality numbers until AutoPos calibration/layout update is completed.

4. RMS gate and speed gate remain disabled in the frozen broadcast baseline.
They should be retuned only after layout calibration.

5. VERSION readback for Anchors remains unreliable (`actual=-`) after OTA. The
runtime behavior and responder readiness are currently the reliable criteria.

## Recommended Next Steps

1. Use the stable Matrix sweep data to proceed with AutoPos solve/calibration.
2. Update `uwb_anchor_layout.c` from the calibrated anchor positions.
3. Re-run 3-Tag broadcast positioning with the updated layout.
4. Retune RMS and speed gates after layout is correct.
5. Investigate Anchor H coverage in broadcast solves.
6. After 3-Tag remains stable, plan 10-Tag scaling validation.
