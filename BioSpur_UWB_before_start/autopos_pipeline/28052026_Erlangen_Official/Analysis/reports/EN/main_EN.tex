\begin{abstract}
This report summarizes the Vicon Motion Capture System ground-truth measurement of the AutoPos system performed in Erlangen on 28 May 2026. The experiment validates AutoPos anchor self-localization, AutoPos Solver and UWB-Tag solver combinations, static UWB-Tag localization, and dynamic RotoArm UWB-Tag measurement. With the AutoPos Solver and UWB-Tag solver combination \case{v4-io/T4}, static UWB-Tag localization reaches $72.7\mm$ median, $171.5\mm$ P95, and $109.8\mm$ RMSE. The dynamic RotoArm UWB-Tag result for the same original UWB-only configuration is $105.8\mm$ median, $231.8\mm$ P95, and $141.3\mm$ sample RMSE. The key mechanism result is delay-layout coupling: Vicon Motion Capture System anchors without matched delay calibration do not automatically improve localization, while Vicon Motion Capture System anchors with re-estimated delay reach $77.7\mm$ RMSE. Monte Carlo anchor-dropout tests, wall/NLOS simulations, FULL/COMPACT CIR, and Phase 4 UWB+IMU results are used to explain error sources, dynamic robustness, and the next engineering path, but they do not replace the Vicon Motion Capture System-UWB validation chain as the main experimental claim.
\end{abstract}

\section{Dataset and Evaluation Objects}

The analysis compares three related coordinate or trajectory sources:
\begin{enumerate}
\item \textbf{Vicon Motion Capture System truth:} reference anchor positions, static tag positions, and dynamic trajectories. It is the evaluation coordinate system, not a deployable input.
\item \textbf{AutoPos UWB self-localized layout:} anchor geometry estimated from UWB measurements. This is the AutoPos self-localization capability under test.
\item \textbf{UWB tag localization and RotoArm UWB-Tag trajectory replay:} tag measurements replayed with different layouts, solvers, delay settings, and filters.
\end{enumerate}

The main configuration in this report is \case{v4-io} for the AutoPos Solver layout result and \case{T4} for the UWB-Tag solver. Other solvers, filters, Monte Carlo tests, simulated NLOS studies, and Phase 4 UWB+IMU results are treated as controls, robustness evidence, or dynamic-extension material.

\section{Anchor Layout: AutoPos vs Vicon Motion Capture System}

\begin{figure}[H]
\centering
\includegraphics[width=0.78\textwidth]{layout_opti_vs_autopos_3d.png}
\caption{Three-dimensional comparison between the Vicon Motion Capture System anchor layout and the AutoPos \case{v4-io} layout.}
\end{figure}

The AutoPos \case{v4-io} layout reaches $105.4\mm$ RMSE after rigid SE(3) alignment to the Vicon Motion Capture System anchor layout. If a Sim(3) scale correction is allowed, the residual drops to $67.1\mm$, with an estimated scale bias of approximately $-4.17\%$. This separation is important: part of the layout discrepancy behaves like global scale or delay-induced bias, while the remaining component is closer to relative anchor-shape error.

The correct interpretation is therefore balanced. AutoPos does not reproduce the Vicon Motion Capture System layout perfectly, but it does recover a usable spatial structure from real UWB measurements. The absolute scale is coupled to the UWB range-delay model and should be discussed together with delay calibration rather than as a pure geometry error.

This is the most important mechanism evidence in the report. It shows that anchor layout, UWB delay, and tag solving form a coupled system. The Vicon Motion Capture System anchor layout is geometrically more accurate, but it can perform poorly if the delay model is not re-estimated for that geometry. Therefore, the main text should not present ``AutoPos versus Vicon Motion Capture System anchors'' as a one-variable comparison. The proper comparison is layout plus its compatible delay calibration.

For the original UWB-only \case{v4-io/T4} configuration, RotoArm UWB-Tag reaches $105.8\mm$ median, $231.8\mm$ P95, and $141.3\mm$ sample RMSE. Even after replacing the layout with Vicon anchors and re-estimating delay, the RotoArm UWB-Tag result remains about $105.6\mm$ median and $200.4\mm$ P95. This negative result is scientifically useful: the dynamic error is not solved by anchor-layout replacement alone.

Timing checks point in the same direction. Clock skew changes pooled P50 by only about $0.11\mm$, and a $0.8\mathrm{ms}$ protocol window corresponds to only about $0.5$--$0.7\mm$ of motion in the measured setup. The hundred-millimeter RotoArm UWB-Tag tail is therefore more plausibly caused by dynamic range bias, body shadowing, antenna orientation, multipath/NLOS, and solver motion assumptions.

Post-solve RotoArm UWB-Tag filters can improve visual smoothness and final trajectory metrics: F4 reaches about $86.3\mm$ median and $158.2\mm$ P95, while F5 reaches about $83.3\mm$ median and $148.6\mm$ P95. These should be described as smoothers, not as calibration results.

This section should be based on the Phase 4 L2/L16/L20 TRUEFULL 5-seed Vicon-truth analysis generated on 5 June 2026, not on the earlier real 6-axis vertical-slice smoke run. The Phase 4 run evaluates three IMU sensor models, L2, L16, and L20, with five seeds S00--S04 per sensor. Each seed contains 1377 runnable rows and is evaluated against the RotoArm UWB-Tag Vicon trajectory tables. The three sensor models are:
\begin{itemize}
\item \case{L2}: MPU6050/JY61P-like 6-axis IMU, representing a low-cost 6-axis baseline.
\item \case{L16}: InvenSense ICM-45686 premium 6-axis IMU, representing a high-performance consumer/robotics-grade 6-axis candidate.
\item \case{L20}: Xsens/Movella MTi-3-5A-T industrial AHRS module, simulated here as accel+gyro, representing an industrial-quality IMU candidate.
\end{itemize}

The Phase 4 headline row is \case{X_A0_U4_P4_L20_I5_T2}. Its 5-seed mean track-median 3D P50/P95/RMSE is $68.4/112.1/75.7\mm$. The same-P UWB P95 is $138.9\mm$, so the same-P P95 improvement is $26.8\mm$; the improvement over B0 P0 is $119.7\mm$; and the RotoArm UWB-Tag radius abs / band P95 is $16.6/105.1\mm$. This means the IMU is not only rescuing a failed system. On top of a strong P4 UWB branch, it still reduces the dynamic tail and improves RotoArm UWB-Tag shape metrics.

\subsection{A0 Baseline and IMU Improvement Modes}

The Phase 4 report also gives A0/U4 UWB baselines by P. The P4 baseline is already strong, with P50/P95/RMSE of $78.2/138.9/86.2\mm$. The P0 raw UWB branch is much worse at $105.8/231.8/132.8\mm$. Therefore, UWB+IMU has two distinct improvement modes:
\begin{enumerate}
\item \textbf{Incremental improvement over a strong UWB baseline:} the best L20 row reduces P4 P95 from $138.9\mm$ to $112.1\mm$, an improvement of $26.8\mm$.
\item \textbf{Rescue from raw or weak UWB:} \case{X_A0_U4_P0_L20_I5_T2} reaches $133.9\mm$ P95, improving over same-P P0 UWB by $97.9\mm$.
\end{enumerate}

These two claims should remain separate. The first is about raising the ceiling of the best UWB pipeline; the second is about suppressing large dynamic failures in weaker UWB branches.

\subsection{Raw-range Branch Is Not Recommended Yet}

The Phase 4 raw-range branch should be reported as a negative control. The best raw row, \case{X_A0_R4_L20_I5_T10}, has P95 $465.4\mm$ and B0 delta $-233.6\mm$, so it is substantially worse than B0 in the current proxy implementation. The practical path is therefore position-branch fusion on \case{A0/U4/Px}, not the current raw-range branch.

\subsection{IMU Claim and Boundary}

IMU should no longer be described only as future work. A better statement is: \textbf{Phase 4 replay/simulation evidence shows that UWB+IMU can reduce RotoArm UWB-Tag P95, suppress spiky jumps, and distinguish sensor-model value across L2/L16/L20.} At the same time, this is still a Vicon-truth evaluated simulation/replay sweep, not a fully embedded real-time Ghost IMU system measurement. The main report should keep UWB-only Vicon Motion Capture System validation as the primary result, then present IMU as the strongest next dynamic-extension result.

\section{CIR: Multipath Evidence Even Under Clear LOS}

CIR should not be treated only as future work. The more accurate position is: \textbf{CIR is not yet a complete LOS/NLOS classifier in this report, but it already provides physical evidence that visually clear LOS anchor self-calibration can still contain multipath tail energy and link-quality differences.} Therefore, CIR belongs in the error-source analysis, not in the main positioning headline.

This report uses two CIR result blocks:
\begin{itemize}
\item \textbf{FULL CIR Sweep10:} \case{CIRRAW_AUTOPOS_SWEEP10_20260602_225118}. This AutoPos Sweep10 run reconstructed 958 complete full-CIR frames out of about 1120 expected frames, or 85.5\% coverage. Each accumulator is 4064 bytes, corresponding to 1016 complex samples.
\item \textbf{F/H 8-hour FULL CIR baseline:} \case{CIRRAW_BSF66F_20260602_020301}. This priority-only F/H capture runs for 8.00 h and contains 31,514 frames. It is used to inspect stable-link waveform and tail/main behavior over time.

The FULL CIR Sweep10 facts are clear. All 8 masters were successful, and every master completed $10/10$ sweep lines, so ordinary ranging was functional. However, link-level full-CIR quality is not uniform. The highest multipath-tail proxy links include \case{C<-G}, \case{G<-C}, \case{F<-G}, \case{E<-H}, \case{G<-F}, and \case{H<-E}, with tail/main proxy around 0.2. Weak SNR-proxy links also concentrate on a subset of pairs, including \case{F<-G}, \case{H<-E}, \case{E<-H}, \case{E<-F}, \case{G<-F}, and \case{G<-C}. This means that clear LOS cannot be modeled as single-path, unbiased, equal-variance ranging for every anchor pair.

Physically, clear LOS only means that the direct path exists. It does not imply that reflected paths are absent. The receiver can still observe delayed energy from the floor, walls, metal structures, mounting hardware, body reflections, or device enclosures. In anchor-anchor self-calibration, this becomes link-specific range bias or variance differences. The link may still be usable, but it should not necessarily have the same weight as a cleaner link.

\section{Recommended Report Structure}

A final written report can follow this structure:
\begin{enumerate}
\item Introduction: validate AutoPos UWB self-localization and tag localization, not just one solver number.
\item Dataset and Coordinate Systems: Vicon Motion Capture System, AutoPos layout, static replay, and RotoArm UWB-Tag.
\item AutoPos Anchor Layout: SE(3) and Sim(3) layout error.
\item Delay-layout Coupling: the four control cases showing why delay must match layout.
\item Static Tag Localization: AutoPos Solver and UWB-Tag solver combination \case{v4-io/T4} at $72.7/171.5/109.8\mm$.
\item Dynamic RotoArm UWB-Tag Evaluation: \case{v4-io/T4} at $105.8/231.8/141.3\mm$ and why timing alone cannot explain the error.
\item Robustness and Simulation: Monte Carlo keep-k and wall/NLOS simulation.
\item CIR Multipath Evidence: use FULL/COMPACT CIR to show tail energy, link-quality differences, and pair-weighting potential under clear LOS.
\item Phase 4 UWB+IMU: detailed L2/L16/L20 dynamic-fusion evidence.
\item Limitations: single site, Vicon Motion Capture System dependence, CIR weights not yet closed-loop validated, and IMU not yet fully embedded.
\item Conclusion: usable self-localization, delay-layout coupling, dynamic propagation challenges, and next-step roadmap.
\end{enumerate}

\section{Conclusion}

The strongest conclusion from the Vicon Motion Capture System ground-truth measurement in Erlangen on 28 May 2026 is that AutoPos UWB self-localization provides a usable anchor geometry and enables approximately 7--11 cm-level static UWB-Tag localization in a real measured field setup. However, UWB accuracy is not determined by geometry alone. Layout, delay calibration, solver choice, motion state, and propagation environment must be treated together. The AutoPos Solver and UWB-Tag solver combination \case{v4-io/T4} should be the static main result; RotoArm UWB-Tag should be presented as the dynamic challenge; Monte Carlo and wall/NLOS simulation should support robustness and error-source discussion; FULL/COMPACT CIR should be presented as physical evidence that clear LOS can still contain multipath and link-quality differences; Phase 4 UWB+IMU is the clearest current path for dynamic robustness improvement.
