\section{Introduction and Dataset Definition}
\label{sec:intro}
% ============================================================

This report presents the first external ground-truth validation of the AutoPos UWB anchor self-localisation system using a Vicon Motion Capture System as a sub-millimetre ground-truth reference.
The measurement was conducted on 28~May~2026 at the Machine Learning and Data Analytics Lab (MaD Lab), Friedrich-Alexander-Universität Erlangen-Nürnberg.
The primary accuracy claim is dataset-bound and is stated as follows.

\begin{quote}
\textbf{Measured static accuracy in the Erlangen Vicon test.}
Using the headline v4-io/T4/F0 pipeline under anchor-locked Vicon rigid registration, AutoPos achieves \SI{72.7}{\milli\metre} median 3D error, \SI{171.5}{\milli\metre} P95 error, and \SI{109.8}{\milli\metre} RMSE over 24 static tag positions.
Each reported static point is one \SI{120}{\second} session-averaged UWB coordinate compared against the corresponding Vicon ground-truth coordinate.
The same evaluation gives \SI{37.4}{\milli\metre} median horizontal error and \SI{61.9}{\milli\metre} median vertical error, with P95 errors of \SI{73.6}{\milli\metre} horizontally and \SI{170.0}{\milli\metre} vertically.
This supports a dataset-specific claim of sub-decimetre median static localisation under this external anchor-locked alignment and centimetre-level horizontal static accuracy in this lab geometry; it is not a universal UWB specification, because anchor layout, tag placement, vertical aperture, residual calibration, and propagation conditions all affect the measured accuracy.
\end{quote}

Dynamic RotoArm accuracy, UWB-internal repeatability, residual delay/range-bias coupling, and offline UWB+IMU fusion are evaluated separately in the later sections.

\subsection{System Under Test}

\textbf{8~UWB anchors} (DWM1001C-Dev modules: nRF52832 SoC + DW1000 UWB transceiver) run broadcast single-sided two-way ranging (broadcast SS-TWR) firmware.
All inter-anchor ranging and anchor self-localisation are performed exclusively from UWB range measurements.

Unlike sensor-fusion-based anchor calibration methods that incorporate inertial measurements~\cite{shi2019anchor}, auxiliary calibration modules~\cite{krapez2020anchor}, or explicit height priors and odometry constraints~\cite{nguyen2025coordinate} directly into the anchor-position estimation, AutoPos uses the ultrasound measurements \textbf{\emph{only}} as a post-calibration gauge input after UWB-only inter-anchor geometry recovery.
The ultrasound observations do not enter the self-calibration cost function; they act as a post-calibration spatial alignment constraint.

\subsection{Dataset Overview}

The dataset includes:
\begin{itemize}[nosep]
  \item 24~static UWB-Tag positions distributed across the anchor array footprint (edge, centre; low, mid, high elevations; multiple antenna facing directions).
        The static set is balanced over four tag-facing groups: each facing group contains 6~positions, with 3~edge and 3~centre positions and 2~low, 2~mid, and 2~high positions.
  \item 17~dynamic RotoArm captures: a rigid wand with two UWB tags (BS2DCE, BSDC91) rotating continuously at fixed angular speed. Across capture sessions, the RotoArm mounting angle was adjusted so that the rotation plane varied between horizontal and vertical orientations; the two tags also followed circular trajectories with different radii.
  \item Vicon Motion Capture System recordings of retroreflective markers on all 8~anchors and on the tag assemblies, providing sub-millimetre 3D ground-truth reference coordinates.
\end{itemize}

\subsection{Solver Nomenclature}
\label{sec:solver_nomenclature}

Throughout this report:
\begin{itemize}[nosep]
  \item \textbf{v1-old, v2, v3-full, v3-lite, v4-io}: AutoPos anchor self-calibration solver versions.
        v4-io denotes the joint robust least-squares solver that minimises inter-anchor range residuals
        using iteratively reweighted least squares with Huber loss,
        solved with a Trust Region Reflective (TRF) optimisation method.
        See \cref{app:layout} for full definitions.
  \item \textbf{T1\,--\,T4}: Pure-UWB tag localisation solver variants, all based on delay-corrected range residuals
        $r_i^{\mathrm{res}} = (\lVert\mathbf{x} - \mathbf{a}_i\rVert + d_{\mathrm{anchor},i} + d_{\mathrm{tag}}) - r_i^{\mathrm{meas}}$
        solved via Gauss--Newton iterations with Huber robust loss ($k=2.0$).
        The variants differ in weighting and temporal context:
        \textbf{T1}~uses per-anchor sigma and Huber weighting only (memory-free);
        \textbf{T2}~adds a range-quality penalty derived from the DW1000 diagnostic fields;
        \textbf{T3}~further adds residual-history (EMA) weighting and a weak temporal prior to the previous position.
        \textbf{T4} (current production solver) applies adaptive branching:
        in full 8-anchor frames it uses the memory-free T1 path to avoid temporal-history bias;
        under anchor dropout it activates T3-like quality/residual-history weighting and the temporal prior.
        All outlier handling is \emph{soft down-weighting}, not hard NLOS link rejection.
        See \cref{app:tag} for full definitions.
  \item \textbf{F0\,--\,F5}: External position filters applied \emph{after} the tag solver on the solved 3D position stream.
        They do not re-process ranges, modify the anchor layout, or change delay calibration.
        F0 is a passthrough (all headline results use F0);
        F1--F3 are progressively more robust online Kalman filters;
        F4 is a deployable fixed-lag smoother;
        F5 is an offline RTS smoother that serves as a diagnostic upper bound.
        See \cref{app:filter} for full definitions.
  \item The \emph{headline configuration} is \textbf{v4-io/T4/F0}: the v4-io anchor layout, current production tag solver, and unfiltered position output.
        All accuracy claims in this report refer to this unfiltered pipeline unless explicitly stated otherwise.
\end{itemize}

Complete mathematical definitions of all solver components are given in \cref{app:solvers}.

\section{Evaluation Methodology}
\label{sec:coord}
% ============================================================

\subsection{Ground-Truth Reference Frame}

The Vicon Motion Capture System provides the primary evaluation reference.
Retro-reflective markers attached to each anchor's DWM1001C module define the anchor phase-centre truth coordinates.
The Vicon-derived 3D positions serve as ground truth throughout this report unless explicitly stated otherwise.

\subsection{Coordinate-Axis Convention}

The raw Vicon and intermediate analysis files use the laboratory export convention in which the vertical coordinate appears as the raw $Y$ axis and the horizontal plane is the raw $X$--$Z$ plane.
For consistency with the BioSpur/AutoPos convention used in the report, all tables and figures relabel the axes as $x/y$ horizontal and $z$ vertical:
\[
    x_{\mathrm{report}} = X_{\mathrm{raw}}, \qquad
    y_{\mathrm{report}} = Z_{\mathrm{raw}}, \qquad
    z_{\mathrm{report}} = Y_{\mathrm{raw}} .
\]
This is a fixed axis relabelling applied before reporting component-wise errors; it is not an additional fitted alignment and it does not change Euclidean 3D distances.
Thus entries labelled ``$x/y$ horizontal'' in the report correspond to the raw $X$--$Z$ horizontal-plane error, and entries labelled ``$z$ vertical'' correspond to the raw vertical $Y$-axis error.

\subsection{Spatial Alignment for AutoPos Anchor Layout}

The raw AutoPos anchor coordinates are internally self-consistent but live in an arbitrary 3D gauge: before comparison with Vicon, the whole layout may be translated, rotated, and mirrored without changing any inter-anchor UWB ranges.
Because the F/G/H ultrasound-height calibration in this dataset is treated as a deployment-gauge input rather than an independently validated Vicon reference (see \cref{sec:us_height}), the primary Vicon evaluation uses an anchor-locked rigid registration.
The rigid registration removes the arbitrary global coordinate frame while preserving the AutoPos layout shape and scale.
The mirror ambiguity inherent in range-only self-calibration is resolved by choosing the handedness with the lower anchor residual against Vicon.

The primary spatial transform is therefore
\[
    \hat{\mathbf{p}}_i = \mathbf{R}\mathbf{p}_i + \mathbf{t},
    \qquad
    \mathbf{R}^{T}\mathbf{R}=\mathbf{I},
\]
with $\det(\mathbf{R})=\pm 1$ to account for the range-only reflection ambiguity.
The fitted transform solves
\[
    \min_{\mathbf{R},\mathbf{t}} \sum_{i \in \{A,\ldots,H\}}
    \left\lVert
    \hat{\mathbf{p}}_i^{\mathrm{AutoPos}}
    -
    \mathbf{p}_i^{\mathrm{Vicon}}
    \right\rVert^2 .
\]
Only the 8 anchor positions are used to estimate this spatial transform.
Tag and RotoArm trajectories are \emph{never} used to fit the transform; the alignment is anchor-locked.
This procedure allows the unknown room-frame origin, orientation, and handedness to be removed, but it does not allow Vicon to scale-correct the deployed AutoPos layout.

For diagnostic purposes, a Sim(3) similarity alignment is also computed by adding one global scale factor to the rigid transform.
The Sim(3) residual is reported only to separate scale-related error from shape error.
It is not used as the primary absolute-accuracy claim, because a deployed AutoPos layout cannot rely on an externally supplied Vicon scale correction.
The corresponding v4-io diagnostic values are reported in \cref{tab:layout,fig:layout_scale}.

\subsection{Temporal Alignment for RotoArm Captures}

The static tag measurements are 120-second stationary sessions: each UWB position estimate is averaged over the session and compared with the corresponding Vicon static position.
They therefore do not require frame-level timestamp alignment.

The dynamic RotoArm measurements are more demanding because the Vicon and UWB systems were not hardware time-synchronised: no shared trigger pulse, GPIO event, or common UTC clock was recorded.
For each RotoArm capture, a single relative time offset $\beta$ is therefore estimated in post-processing.
The UWB sample times are shifted by $\beta$, the Vicon trajectory is linearly interpolated at the shifted UWB sample times, and $\beta$ is selected by minimising the median 3D trajectory residual over the overlapping circular-motion samples of the two wand-mounted tags.
This is a coarse-to-fine scalar search using the primary v4-io/T4 trajectory; the selected capture-level offset is then frozen and reused for all other layout, tag-solver, and IMU-replay comparisons.

This procedure uses the closest available post-processed offset for each capture, but it is still not equivalent to physical time synchronisation.
It corrects the unknown capture start-time offset, but it is not a hardware latency measurement and cannot remove residual timestamp jitter, clock drift, or ambiguity caused by the periodic circular motion.
Because $\beta$ is selected by minimising a trajectory residual, the remaining timing uncertainty can bias the reported dynamic error in either direction: imperfect alignment can inflate the error, while best-fit phase selection can reduce the reported error relative to an unfitted clock reference.
Consequently, RotoArm absolute trajectory errors should be interpreted as best-fit post-processed dynamic errors, not as purely clock-synchronised UWB dynamic errors.
The static-position results are not affected by this limitation.

\subsection{Ultrasound Height Reference}
\label{sec:us_height}

The deployed AutoPos system uses ultrasound-measured heights for anchors F, G, H.
This remains the intended deployable configuration: the layout is determined from UWB inter-anchor ranges and then assigned a physical vertical gauge using the US height inputs, not from Vicon coordinates.
However, the 28~May dataset does not support an independent US-height accuracy claim.
The H-anchor ultrasound measurement is suspected to be affected by the short \SI{20}{\centi\metre} carbon-fibre extension used during the measurement, which may have caused the sensor to range to an unintended local surface or support structure.
The F and G sensors used longer \SI{30}{\centi\metre} carbon-fibre extensions and show smaller height discrepancies against Vicon, whereas H shows the largest discrepancy.
For this reason, the ultrasound data are reported as a system component and deployment-gauge input, but not as a separate validated ground-truth source.
The primary numerical results in this report therefore use the anchor-locked rigid Vicon registration from \cref{sec:coord}.

\subsection{Evaluation Objects}

Throughout this report we distinguish two static-position quantities.
\textbf{Absolute accuracy} is the Euclidean 3D error between an estimated position and its Vicon ground-truth position (reported as median, P95, and RMSE); it is the Vicon-referenced error and reflects systematic bias plus random error.
\textbf{Repeatability} or \textbf{precision} (denoted $\sigma_{3D}$) is the 3D spatial spread of repeated UWB estimates at a fixed static position, computed relative to that position's own UWB cluster rather than relative to the Vicon coordinate.
It is therefore an internal UWB stability metric, not a Vicon absolute-error metric.
The two are independent: post-processing can improve repeatability without changing absolute accuracy.

For RotoArm data the tag is continuously moving, so the static repeatability definition does not apply.
The dynamic section therefore reports two different quantities: UWB trajectory error against Vicon truth, and RotoArm geometric self-consistency metrics such as radius-difference RMS and turn-centre repeatability.
The self-consistency metrics can be computed from either the Vicon trajectory or the UWB trajectory using the same circle-fitting procedure; they are useful physical-consistency checks, but they are not substitutes for Vicon-referenced dynamic accuracy.

\vspace{0.4em}
\begin{itemize}[topsep=4pt,itemsep=4pt]
\item \textbf{Anchor layout:} 8 anchor positions, compared primarily via anchor-locked rigid Vicon registration; Sim(3) scale fitting is diagnostic only.
  \item \textbf{Static tag positions:} 24 positions, each recorded as one 120-second static session ($\sim$1201 frames).
        Per-position accuracy is the Euclidean 3D error between the session-averaged UWB tag coordinate and the Vicon truth position.
  \item \textbf{RotoArm UWB-Tag trajectories:} 17 captures of continuous circular motion.
        Per-sample 3D error is computed after temporal alignment (see \cref{sec:roto}).
\end{itemize}

\subsection{Scale Bias Interpretation}

The diagnostic reduction from \SI{105.4}{\milli\metre} (rigid registration) to \SI{67.1}{\milli\metre} (Sim(3)), together with \cref{fig:layout_scale}, indicates that a substantial fraction of the absolute layout error is a coherent scale offset rather than random shape distortion.
\Cref{fig:layout_scale} makes this visible directly: 27 of 28 anchor-pair distances are longer in AutoPos than in Vicon, with a median pairwise scale error of approximately +4.1\%.
This scale offset is consistent with the known coupling between layout geometry and UWB ranging delay: the DW1000 firmware hardcodes the antenna delay at 16436~DTU, and the solver's layout-level residual delay corrections (\texttt{d\_anchor\_mm}, \texttt{tag\_delay\_mm}) absorb remaining delay--geometry ambiguity into the coordinate frame.
The Sim(3) diagnostic confirms that the dominant error mode is scale-like, not random topology distortion.

This behaviour is consistent with delay--geometry coupling in UWB self-calibration.
The anchor accuracy claim remains the rigid-registered result in \cref{tab:layout}; the Sim(3) scale correction is diagnostic only.

\section{Delay--Layout Coupling}
\label{sec:delay}
% ============================================================

This section presents the clearest mechanism-level result of the measurement campaign.
It demonstrates that anchor geometry and residual delay/range-bias calibration are coupled quantities that cannot be separated naively.
The term ``delay correction'' in this section refers to the solver's fitted residual correction terms, not to a pure hardware antenna-delay measurement.
These residual corrections can absorb fixed antenna-delay mismatch, per-device range bias, and geometry-dependent error left after the nominal DW1000 antenna-delay setting.

A four-way ablation was performed by combining two layout sources (AutoPos v4-io self-calibrated coordinates, Vicon-measured coordinates) with different residual-correction treatments.
In \cref{tab:delay_coupling}, ``Vicon-measured anchor coordinates'' means that the UWB tag solver is given the anchor positions measured by Vicon instead of the anchor positions estimated by AutoPos from inter-anchor UWB ranging.
It does not refer to a different UWB-anchor hardware setup.

\subsection{Key Findings}

\begin{enumerate}[nosep]
  \item \textbf{No residual correction:} using Vicon-measured coordinates without residual correction yields \SI{311}{\milli\metre} RMSE---the worst of all four configurations.
        Ground-truth geometry alone is insufficient.
  \item \textbf{Transplanting AutoPos residual corrections} to the Vicon frame reduces the error to \SI{252}{\milli\metre}, but the corrections are conditioned on the AutoPos coordinate frame and do not transfer well.
  \item \textbf{Re-estimating residual corrections on the Vicon frame} gives the lowest RMSE in this ablation (\SI{78}{\milli\metre}), confirming that delay--geometry coupling is a major error source.
  \item \textbf{AutoPos self-calibration} achieves \SI{109}{\milli\metre} RMSE in this ablation.
        It remains competitive because it co-fits geometry and residual corrections in a self-consistent frame.
\end{enumerate}

Prior UWB calibration work already shows that anchor coordinates and antenna-delay or range-bias parameters are accuracy-critical, and many systems estimate them jointly or with additional calibration infrastructure~\cite{shah2022node,piavanini2022self,nguyen2025coordinate}.
Some work treats hardware antenna delay as a separately calibrated, largely transferable quantity~\cite{shalaby2023calibration}, while robotics calibration work has shown that UWB sensor error models can be difficult to generalise across anchor setups and environments~\cite{lutz2019visual}.
The novelty here is not the existence of delay--geometry coupling, but the explicit four-way ablation in \cref{tab:delay_coupling} showing a concrete transfer failure: in the same physical deployment, Vicon-measured anchor coordinates degrade tag localisation unless the residual corrections are re-estimated in the Vicon coordinate frame.
To our knowledge, this is the first explicit four-way ablation demonstrating that externally measured optical ground-truth anchor coordinates cannot be substituted for a self-calibrated UWB layout without re-estimating residual delay/range-bias corrections in the same coordinate frame.

This result has direct implications for UWB system design and for the interpretation of ground-truth validation: optical reference coordinates cannot simply be dropped into a UWB solver as a ``better layout'' without re-estimating the residual correction parameters.
The fitted residual corrections are frame-conditioned quantities.

\section{Dynamic RotoArm UWB-Tag Evaluation}
\label{sec:roto}
% ============================================================

All accuracy metrics in this section are \textbf{absolute accuracy} (per-sample 3D error to Vicon ground truth).
Static repeatability is not reported for the RotoArm data because repeatability requires repeated samples at the same stationary tag position.
Here the tags are continuously moving, so frame-to-frame variation mainly reflects motion along the circular trajectory rather than jitter around one fixed point.

\subsection{Temporal Alignment}

As defined in \cref{sec:coord}, the Vicon Motion Capture System and UWB system share \emph{no hardware time synchronisation}.
The RotoArm evaluation therefore uses one post-processed relative time offset per capture.
The median offset is \SI{45.5}{\second} (range \SIrange{37.7}{48.7}{\second}); this range reflects differing Vicon capture start times, not alignment instability---the median alignment score is \SI{101.8}{\milli\metre}, consistent with the static positioning error floor.

The offset is estimated from one solver configuration and reused across all layout/solver combinations.
Residual timing error contributes directly to the reported dynamic error, but the post-hoc best-fit offset can bias the result in either direction.
It can leave residual phase error that inflates the trajectory error, or it can reduce the error by selecting the phase that best matches the same trajectory residual later reported.
This limits the strength of causal attribution: the dynamic error tail cannot be fully decomposed into time-alignment error versus UWB-intrinsic dynamic error (range bias, antenna orientation, body obstruction) without hardware-synchronised ground truth.

\subsection{Negative Result: Vicon Anchors Do Not Solve Dynamic Error}

Even with Vicon-measured anchor coordinates and re-estimated residual corrections, the dynamic RotoArm error remains approximately \SI{106}{\milli\metre} median and \SI{200}{\milli\metre} P95.
This is a key negative finding: the $\sim$\SI{100}{\milli\metre}--\SI{200}{\milli\metre} dynamic error tail is \emph{not explained by anchor geometry alone}.

More plausible causes include:
dynamic range bias (Doppler-like effects on the UWB pulse),
antenna radiation pattern and orientation changes during rotation,
body/wand obstruction creating transient NLOS conditions,
multipath from the rotating assembly,
and solver assumptions that do not account for motion state.

\section{Wall/NLOS Simulation}
\label{sec:wall}
% ============================================================

To contextualise the propagation environment's role in UWB accuracy, a Monte Carlo ray-tracing simulation was conducted.
This simulation models the effect of nearby walls and metallic objects on UWB ranging and self-calibration accuracy.
It is presented as discussion evidence, not as direct validation.

\subsection{Simulation Methodology}

The simulation is a first-order UWB propagation-risk study, not a replay of the complete AutoPos solver.
It uses an idealised paired-anchor layout with 8 anchors at the corners of a \SI{3}{\metre} by \SI{3}{\metre} horizontal footprint and two height layers separated by \SI{1.4}{\metre}.
Candidate tag positions are sampled on a \SI{25}{\centi\metre} grid inside the volume, giving 847 tag points.
For each tag point, ideal ranges to all 8 anchors are perturbed by a stochastic range-error model and then converted to position error using the local multilateration geometry matrix.
The reported P95 values are therefore distributional predictions over the simulated tag grid and noise trials; they should be read as propagation-risk evidence rather than direct validation.

The baseline clear-LOS model uses zero-mean Gaussian range noise with \SI{3}{\centi\metre} standard deviation.
Wall cases add a positive range-bias component and extra variance that increase when either the tag or anchor is close to a wall and when the link is near-grazing to the wall surface.
The biased links also receive a positive-tailed random component to represent NLOS/multipath error tails.
Phase~2 adds a coarse local-reflector model: six random metal/equipment boxes are placed near the layout boundary, based on photographs of the 28 May 2026 FAD Lab Erlangen test setup, and these boxes add additional proximity-dependent range bias and variance.
Only side walls are modelled as NLOS sources; the nominal ceiling height is \SI{2.5}{\metre}, but ceiling reflections are not included.

The study sweeps anchor-to-wall distance from \SI{0}{\centi\metre} to \SI{300}{\centi\metre} for a 4-wall room enclosure.
Three material phases are compared:
\begin{itemize}[nosep]
  \item Phase~1: default heavy reflective wall model.
  \item Phase~2: Phase~1 plus random metal/equipment boxes near the layout boundary, with their placement inspired by photographs of the 28 May 2026 FAD Lab Erlangen test setup.
  \item Phase~3: wall material sensitivity (drywall, gypsum, sand-lime brick, reinforced concrete).
\end{itemize}
Phase~1 and Phase~3 use 128 range-noise trials per tag point; Phase~2 uses 96 range-noise trials per tag point and 12 independent metal-box seeds.

\section{Limitations and Future Work}
\label{sec:limitations}
% ============================================================

\subsection{Measurement Limitations}

\begin{enumerate}[nosep]
  \item \textbf{No hardware time synchronisation.}
        Vicon and UWB lack a shared clock.
        The per-capture time offset is estimated post hoc, so the reported dynamic error is a best-fit trajectory error rather than a hardware-synchronised error.
        Residual misalignment can inflate the error, while best-fit phase selection can also reduce the reported error relative to an unfitted clock reference.
        Future measurements should use GPIO-pulse or event-based hardware synchronisation.

  \item \textbf{Single measurement site.}
        All data comes from one lab environment in Erlangen.
        The propagation conditions (large open space, approximately \SI{1}{\metre} to the nearest wall, limited nearby metal clutter) are comparatively favourable.
        Performance in cluttered, NLOS-rich, or multi-room environments may differ substantially.

  \item \textbf{Static tag positions are discrete.}
        The 24 tag positions provide spatial coverage but not continuous spatial sampling.
        Error interpolation between positions is approximate.

  \item \textbf{RotoArm is a constrained dynamic scenario.}
        Continuous circular motion at fixed radius does not represent general 3D human motion.
        The BioSpur full-body tracking application will require validation with unconstrained movement trajectories.

  \item \textbf{Phase~4 IMU results are replay/simulation.}
        The IMU fusion evidence is based on offline replay with synthetic sensor models, not closed-loop embedded operation.
        Hardware-integrated IMU validation is required before claiming real-time fusion performance.
\end{enumerate}

\subsection{Identified Error Sources}

\begin{enumerate}[nosep]
  \item \textbf{Delay--layout coupling.}
        The +4.36\% pairwise scale bias (equivalently, a Sim(3) fitted scale of 0.9583) and the residual-correction ablation results confirm that residual delay/range-bias calibration and layout geometry are coupled.
        Further WHY-analysis (per-tag antenna delay decomposition, two-way tag$\times$anchor median-polish) is ongoing.

  \item \textbf{Distance-dependent static error.}
        The static distance-to-centroid diagnostic in \cref{fig:static_distance} shows that peripheral tag positions tend to have larger errors, consistent with GDOP and range-bias accumulation away from the array centre.

  \item \textbf{Dynamic error floor at $\sim$\SI{100}{\milli\metre}.}
        Neither layout improvement nor delay re-calibration reduces the dynamic median below $\sim$\SI{100}{\milli\metre}, pointing to UWB-intrinsic dynamic factors.

  \item \textbf{Multipath in clear LOS.}
        CIR evidence shows that visually clear LOS does not guarantee single-path UWB propagation.
        Tail energy ratios of $\sim$0.2 on several links suggest floor/ceiling reflections contribute to range bias.

  \item \textbf{Dropout geometry risk.}
        The ML/DOP analysis shows that some surviving-4 anchor subsets have poor height-axis observability.
        Runtime confidence should depend on the active anchor set, not only on the number of available anchors.
\end{enumerate}

\subsection{Next Steps}

\begin{itemize}[nosep]
  \item Complete WHY\#8--\#9 analysis: per-tag antenna delay decomposition and within-scenario anchor consistency checks.
  \item OTA firmware update of remaining tags (BS2DCE/BSDC91) to b57 for runtime layout calibration via APOS BLE push.
  \item Hardware-synchronised Vicon--UWB validation for unambiguous dynamic error attribution.
  \item Closed-loop embedded IMU fusion measurement with physical IMU sensors, not replay or simulation.
  \item Expand real Vicon-labeled layouts before supervised ML training; the current ML/DOP analysis is useful only for deployment-risk screening.
  \item Ecological validation: multi-room, NLOS-rich environment with $N \geq 10$ participants for BioSpur full-body tracking.
\end{itemize}

\section{Conclusion}
\label{sec:conclusion}
% ============================================================

This report presents the first Vicon Motion Capture System ground-truth validation of the AutoPos UWB self-localisation system.
The key results are:

\begin{enumerate}[nosep]
  \item \textbf{Anchor layout accuracy:}
        Under anchor-locked rigid registration against Vicon, the v4-io solver recovers anchor geometry with \SI{92.8}{\milli\metre} median error and \SI{105.4}{\milli\metre} RMSE.
        The Sim(3) diagnostic reduces the residual to \SI{67.1}{\milli\metre}, showing that part of the residual is a coherent scale bias arising from delay--geometry coupling.

  \item \textbf{Delay--layout coupling:}
        In the median-estimator ablation of \cref{tab:delay_coupling}, using Vicon-measured coordinates \emph{without} re-estimating residual corrections produces \SI{311}{\milli\metre} static tag RMSE, worse than the AutoPos v4-io row in the same ablation (\SI{109}{\milli\metre} RMSE).
        This demonstrates that layout and residual correction terms are coupled quantities that must be co-fitted.

  \item \textbf{Static tag localisation:}
        Under anchor-locked Vicon rigid registration, the headline v4-io/T4/F0 pipeline achieves \SI{72.7}{\milli\metre} median, \SI{171.5}{\milli\metre} P95, and \SI{109.8}{\milli\metre} RMSE across 24 positions.
        This is the external-alignment validation result, not a separate validation of the deployed US-gauge frame.

  \item \textbf{Dynamic tag localisation:}
        RotoArm evaluation yields \SI{106}{\milli\metre} median and \SI{232}{\milli\metre} P95.
        This error is not removed by using Vicon-measured anchor coordinates, indicating that the dynamic error floor is not explained by anchor layout alone.

  \item \textbf{IMU fusion potential:}
        Offline replay with simulated IMU models reduces Phase~4 track-median P95 from \SI{138.9}{\milli\metre} for the same-P UWB baseline to \SI{112.1}{\milli\metre} with L20.
        Relative to the B0/P0 UWB baseline, the improvement is \SI{119.7}{\milli\metre}; on the spiky R01/BS2DCE track, all three tested IMU tiers eliminate $>$\SI{200}{\milli\metre} jump events.

  \item \textbf{Propagation environment:}
        CIR analysis confirms that clear LOS does not imply ideal single-path UWB, and wall/NLOS simulation quantifies the safe clearance distance ($\geq$\SI{1}{\metre}).

  \item \textbf{Deployment-risk screening:}
        Preliminary ML/DOP screening is not yet training-ready, but it identifies surviving-4 height-axis risk as an operational concern for high-reliability deployments.
\end{enumerate}

In this Vicon dataset, the headline pipeline supports sub-decimetre median static localisation and approximately decimetre-class static RMSE under anchor-locked Vicon rigid registration.
In this dataset, the ultrasound height sensors are retained as a system component but are not used as an independent accuracy claim because the H-anchor height measurement is suspected to be affected by its short carbon-fibre extension.
The delay--layout coupling insight---that ground-truth geometry is insufficient without matched residual delay/range-bias calibration---is a finding with implications beyond this specific system.

\section{Solver Component Definitions}
\label{app:solvers}
% ============================================================

This appendix provides the complete mathematical definitions of the three solver layers referenced throughout this report:
the anchor layout solver (V-series), the per-frame tag position solver (T-series), and the external position filter (F-series).
The production pipeline is \textbf{v4-io/T4/F0}.

% ------------------------------------------------------------
\subsection{Anchor Layout Solvers (V1--V4-io)}
\label{app:layout}
% ------------------------------------------------------------

All layout solvers take directed inter-anchor UWB sweep ranges as input and output anchor coordinates $\mathbf{x}_i \in \mathbb{R}^3$ for $i \in \{A,\ldots,H\}$.
Some versions additionally estimate per-anchor residual delay corrections $d_i$.

\paragraph{Gauge convention.}
All layouts are computed in a relative coordinate frame with three gauge constraints:
anchor A at the origin, B on the positive $x$-axis, C in the $xy$-plane.
This removes the six rigid-body degrees of freedom (three translations, three rotations) inherent in distance-only observations.
The gauge does \emph{not} imply that A coincides with any external reference origin.

\paragraph{Pair range fusion.}
Before layout estimation, directed range measurements $r_{i \to j}$ and $r_{j \to i}$ are fused into a single symmetric distance estimate $\hat{d}_{ij}$ per anchor pair.
Three fusion methods are used:
\begin{align}
  \text{V1 (mean):} \quad & \hat{d}_{ij} = \operatorname{mean}(r_{i \to j} \cup r_{j \to i}) \\[3pt]
  \text{V2 (IVW):} \quad & \hat{d}_{ij} = \frac{\sigma_{ji}^2 \bar{r}_{ij} + \sigma_{ij}^2 \bar{r}_{ji}}{\sigma_{ij}^2 + \sigma_{ji}^2} \\[3pt]
  \text{V3 (MAD/MVUE):} \quad & \hat{d}_{ij} = \frac{\hat{\sigma}_{ji}^2 \tilde{r}_{ij} + \hat{\sigma}_{ij}^2 \tilde{r}_{ji}}{\hat{\sigma}_{ij}^2 + \hat{\sigma}_{ji}^2}
\end{align}
where $\bar{r}$ denotes the sample mean, $\tilde{r}$ the sample median, $\sigma^2$ the sample variance, and $\hat{\sigma} = 1.4826 \cdot \mathrm{MAD}$ the robust scale estimate.

\paragraph{V1-old: Classical MDS.}
Embeds the pair distance matrix into $\mathbb{R}^3$ via eigendecomposition of the double-centred squared-distance matrix.
No nonlinear refinement, no delay estimation ($d_i = 0\ \forall\,i$).

\paragraph{V2: MDS + regularised NLS.}
MDS initialisation followed by nonlinear least-squares refinement of
$\sum_{(i,j)} \bigl(\lVert\mathbf{x}_i - \mathbf{x}_j\rVert - \hat{d}_{ij}\bigr)^2$
with a weak vertical-spread regulariser ($\lambda \sum_i (z_i - \bar{z})^2$, $\lambda$ annealed over three passes).
No delay estimation ($d_i = 0$).

\paragraph{V3-lite: Robust fusion, no delay.}
Uses V3 MAD/MVUE pair fusion with MDS + NLS refinement.
Identical solver structure to V2 but with the robust pair distances.
No delay estimation ($d_i = 0$).

\paragraph{V3-full: Tukey IRLS with alternating delay.}
Alternates between:
\begin{enumerate}[nosep]
  \item \textbf{Coordinate update}: Tukey bisquare reweighted least squares on
    $r_{ij} = \lVert\mathbf{x}_i - \mathbf{x}_j\rVert + d_i + d_j - \hat{d}_{ij}$,
    with Tukey threshold $c = 4.685\,\hat{\sigma}$ and $\hat{\sigma} = \mathrm{MAD}(\{r_{ij}\})$.
  \item \textbf{Delay update}: For each anchor $i > 0$, $d_i \leftarrow \operatorname{median}_j\bigl(\hat{d}_{ij} - \lVert\mathbf{x}_i - \mathbf{x}_j\rVert - d_j\bigr)$.
\end{enumerate}
Iterated until convergence ($\Delta\mathbf{x} < 0.1$\,mm and $\Delta d < 0.05$\,mm) or 50 iterations. Anchor~A is the delay reference ($d_A = 0$).

\paragraph{V4-io: Joint Huber bounded-delay (production solver).}
Jointly estimates coordinates and delays by minimising:
\begin{equation}
  \min_{\mathbf{x},\,\mathbf{d}} \sum_{(i,j)} \rho_H\!\left(\frac{\lVert\mathbf{x}_i - \mathbf{x}_j\rVert + d_i + d_j - \hat{d}_{ij}}{15}\right)
  + \sum_{i>0} \left(\frac{d_i}{20}\right)^{\!2}
  + \Phi_{\mathrm{prior}}(\mathbf{x})
  \label{eq:v4io}
\end{equation}
where $\rho_H$ is the Huber loss with $f_{\mathrm{scale}} = 2.0$, delay is bounded $|d_i| \leq 60$\,mm, and $\Phi_{\mathrm{prior}}$ is a soft two-layer vertical prior:
\begin{itemize}[nosep]
  \item $d_D^{(z)}$ deviation from the lower-layer (A/B/C) median: $\sigma = 180$\,mm.
  \item E/F/G/H deviation from the upper-layer median: $\sigma = 220$\,mm.
  \item Layer gap bounded: $[450, 2600]$\,mm.
\end{itemize}
Solved via Trust Region Reflective (TRF) in \texttt{scipy.optimize.least\_squares}, initialised from V3-lite MDS+NLS.
Anchor~A is the delay reference ($d_A = 0$). Denominators (15, 20\,mm) set the relative weighting between range residuals and delay regularisation.

% ------------------------------------------------------------
\subsection{Tag Position Solvers (T1--T4)}
\label{app:tag}
% ------------------------------------------------------------

All tag solvers are pure-UWB, single-frame, delay-corrected trilateration solvers.
Given anchor coordinates $\mathbf{a}_i$, ranges $r_i$, per-anchor residual delay $d_{\mathrm{anchor},i}$, and common tag delay $d_{\mathrm{tag}}$, each solver estimates the tag position $\mathbf{x}$ by iterative Gauss--Newton on the residual vector:
\begin{equation}
  e_i = \lVert\mathbf{x} - \mathbf{a}_i\rVert + d_{\mathrm{anchor},i} + d_{\mathrm{tag}} - r_i
  \label{eq:tag_residual}
\end{equation}

The effective per-range sigma is:
\begin{equation}
  \sigma_{\mathrm{eff},i} = \max\!\bigl(\sigma_{\mathrm{anchor},i},\; 5\bigr) \;\cdot\; \alpha_{\mathrm{quality},i} \;\cdot\; \alpha_{\mathrm{residual},i}
  \label{eq:sigma_eff}
\end{equation}

\paragraph{Quality penalty $\alpha_{\mathrm{quality}}$ (T2+).}
\begin{equation}
  \alpha_{\mathrm{quality},i} = \operatorname{clamp}\!\left(1 + 1.5 \left(\frac{100 - \bar{q}_i}{50}\right)^{\!2},\; 1,\; 4\right)
\end{equation}
where $\bar{q}_i$ is the average of instantaneous and EMA-smoothed DW1000 quality fields.
T1 sets $\alpha_{\mathrm{quality}} = 1$.

\paragraph{Residual-history penalty $\alpha_{\mathrm{residual}}$ (T3+).}
\begin{equation}
  \alpha_{\mathrm{residual},i} = \operatorname{clamp}\!\left(1 + 0.5 \cdot \frac{\max(0,\; \mathrm{EMA}_i - 120)}{80},\; 1,\; 2.5\right)
\end{equation}
where $\mathrm{EMA}_i$ is the exponentially weighted moving average of $|e_i|$ (decay $\alpha = 0.3$).
T1 and T2 set $\alpha_{\mathrm{residual}} = 1$.

\paragraph{Robust weighting.}
The normalised residual $\tilde{e}_i = e_i / \sigma_{\mathrm{eff},i}$ is reweighted with Huber loss ($k = 2.0$):
\begin{equation}
  w_i = \begin{cases} 1 & \text{if } |\tilde{e}_i| \leq 2 \\ 2 / |\tilde{e}_i| & \text{otherwise} \end{cases}
\end{equation}

\paragraph{Temporal prior (T3+).}
When a previous position $\mathbf{x}_{\mathrm{prev}}$ is available, the normal equations include:
\begin{equation}
  \mathbf{H} \mathrel{+}= \sigma_{\mathrm{prior}}^{-2}\,\mathbf{I}_3, \qquad
  \mathbf{g} \mathrel{+}= \sigma_{\mathrm{prior}}^{-1}\,(\mathbf{x} - \mathbf{x}_{\mathrm{prev}}) / \sigma_{\mathrm{prior}}
\end{equation}
with $\sigma_{\mathrm{prior}} = 180$\,mm. T1 and T2 do not use a temporal prior.

\paragraph{T4 adaptive branching.}
T4 applies context-dependent method selection per frame:
\begin{equation}
  \text{T4}(n) = \begin{cases}
    \text{T1 (memory-free)} & \text{if } n \geq 8 \\
    \text{T3 (quality + residual EMA + prior)} & \text{if } n < 8
  \end{cases}
\end{equation}
In full 8-anchor frames, T4 avoids temporal-history bias by using the stateless T1 path.
Under anchor dropout ($n < 8$), T4 activates quality weighting, residual-history weighting, and the temporal prior.

\paragraph{Solver parameters.}
All variants share: $\mathrm{max\_iters} = 8$, $\mathrm{max\_step} = 500$\,mm, $\mathrm{convergence} = 0.02$\,mm.
All outlier handling is \emph{soft down-weighting}; the C implementation does not execute a hard anchor-rejection loop.

\subsection{External Position Filters (F0--F5)}
\label{app:filter}
% ------------------------------------------------------------

These filters operate on the solved 3D position stream $\mathbf{z}_k = [x_k, y_k, z_k]^\top$ output by the tag solver.
They do not re-process UWB ranges, modify the anchor layout, or change delay calibration.

\paragraph{State and motion model (F1--F5).}
All Kalman-based filters use a 6-state constant-velocity model:
\begin{equation}
  \mathbf{x} = [p_x,\, p_y,\, p_z,\, v_x,\, v_y,\, v_z]^\top, \qquad
  \mathbf{F} = \begin{bmatrix} \mathbf{I}_3 & \Delta t\,\mathbf{I}_3 \\ \mathbf{0} & \mathbf{I}_3 \end{bmatrix}
\end{equation}
Process noise $\mathbf{Q}$ is parameterised by an acceleration standard deviation $\sigma_a$:
\begin{equation}
  \mathbf{Q}_{pp} = \tfrac{1}{4}\Delta t^4 \sigma_a^2 \mathbf{I}_3, \quad
  \mathbf{Q}_{pv} = \tfrac{1}{2}\Delta t^3 \sigma_a^2 \mathbf{I}_3, \quad
  \mathbf{Q}_{vv} = \Delta t^2 \sigma_a^2 \mathbf{I}_3
\end{equation}

\paragraph{F0: Passthrough.}
$\hat{\mathbf{p}}_k = \mathbf{z}_k$. No filtering. All headline results use F0.

\paragraph{F1: Online constant-velocity Kalman filter.}
Standard predict--update cycle with fixed $\sigma_a$ and measurement noise $\mathbf{R} = \operatorname{diag}(\sigma_r^2, \sigma_r^2, (1.25\sigma_r)^2)$ where $\sigma_r$ is derived from the tag solver's residual RMS.

\paragraph{F2: Robust constant-velocity Kalman filter.}
Identical to F1 but with innovation gating: if the normalised innovation squared
$\mathrm{NIS} = \mathbf{y}^\top \mathbf{y}\, /\, \sigma_r^2 > 25$,
the measurement covariance is inflated $\mathbf{R} \leftarrow \mathbf{R} \cdot \min(30,\, \mathrm{NIS}/9)$.
This soft-rejects jump outliers without discarding the measurement entirely.

\paragraph{F3: Adaptive robust Kalman filter.}
As F2, with speed-adaptive process noise:
\begin{equation}
  \sigma_a = \begin{cases}
    \sigma_a^{\mathrm{high}} & \text{if } \lVert\mathbf{z}_k - \mathbf{z}_{k-1}\rVert / \Delta t > v_{\mathrm{threshold}} \\
    \sigma_a^{\mathrm{low}}  & \text{otherwise}
  \end{cases}
\end{equation}
Static context: $\sigma_a^{\mathrm{low}} = 300$, $\sigma_a^{\mathrm{high}} = 2000$, $v_{\mathrm{threshold}} = 500$\,mm/s.
Dynamic (ROTO) context: $\sigma_a^{\mathrm{low}} = 900$, $\sigma_a^{\mathrm{high}} = 3200$, $v_{\mathrm{threshold}} = 900$\,mm/s.

\paragraph{F4.}
The fixed-lag smoother applies a bounded-window weighted average after F2/F3:
\begin{equation}
  \hat{\mathbf{p}}_k = \frac{\sum_{j=k-L}^{k+L} w_j \,\hat{\mathbf{p}}_j^{\mathrm{fwd}}}{\sum_{j=k-L}^{k+L} w_j}, \qquad
  w_j = \frac{1}{1 + |j - k|}
\end{equation}
with lag $L = 5$ (ROTO) or $L = 8$ (static). Deployable with a known output latency of $L / f_s$ seconds.

\paragraph{F5: Rauch--Tung--Striebel (RTS) offline smoother.}
Full-sequence forward Kalman filtering followed by a backward smoothing pass:
\begin{equation}
  \hat{\mathbf{x}}_k^s = \hat{\mathbf{x}}_k^f + \mathbf{C}_k \bigl(\hat{\mathbf{x}}_{k+1}^s - \hat{\mathbf{x}}_{k+1}^{-}\bigr), \qquad
  \mathbf{C}_k = \mathbf{P}_k^f \mathbf{F}_{k+1}^\top (\mathbf{P}_{k+1}^{-})^{-1}
\end{equation}
where superscripts $f$, $s$, $-$ denote filtered, smoothed, and predicted estimates.
F5 uses future samples and \emph{cannot} be deployed in real time.
It serves as a diagnostic upper bound on achievable accuracy for a given tag solver.
