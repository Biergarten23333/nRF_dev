\section{Introduction and Dataset Definition}
\label{sec:intro}
% ============================================================

This report presents the first external ground-truth validation of the AutoPos UWB anchor self-localisation system using a Vicon Motion Capture System as a sub-millimetre ground-truth reference.
The measurement was conducted on 28~May~2026 at the Machine Learning and Data Analytics Lab (MaD Lab), Friedrich-Alexander-Universität Erlangen-Nürnberg.
The primary accuracy claim is dataset-bound and is stated as follows.

\begin{quote}
\textbf{Measured static accuracy in the Erlangen Vicon test.}
Using the headline v4-io/T4/F0 pipeline under anchor-locked Vicon rigid registration, AutoPos achieves \SI{72.7}{\milli\metre} median 3D error, \SI{171.5}{\milli\metre} P95 error, and \SI{109.8}{\milli\metre} RMSE over 24 static tag positions.
Each reported static point is one \SI{120}{\second} session-averaged UWB coordinate compared against the corresponding Vicon ground-truth coordinate.
The same evaluation gives \SI{37.4}{\milli\metre} median horizontal error and \SI{61.9}{\milli\metre} median vertical error, with P95 errors of \SI{73.6}{\milli\metre} horizontally and \SI{170.0}{\milli\metre} vertically.
This supports a dataset-specific claim of sub-decimetre median static localisation under this external anchor-locked alignment and \SI{37.4}{\milli\metre} median horizontal error in this lab geometry; it is not a universal UWB specification, because anchor layout, tag placement, vertical aperture, residual calibration, and propagation conditions all affect the measured accuracy.
\end{quote}

Dynamic RotoArm accuracy, UWB-internal repeatability, residual delay/range-bias coupling, and offline UWB+IMU fusion are evaluated separately in the later sections.

For the tag assemblies, Vicon therefore provides a rigid-body pose first, not the final UWB point directly.
The reported tag ground-truth coordinate is the reconstructed antenna centre obtained from the marker-holder rigid body and the caliper-measured pivot-to-antenna offset.

Unlike sensor-fusion-based anchor calibration methods that incorporate inertial measurements~\cite{shi2019anchor}, auxiliary calibration modules~\cite{krapez2020anchor}, or explicit height priors and odometry constraints~\cite{nguyen2025coordinate} directly into the anchor-position estimation, AutoPos uses the ultrasound measurements \textbf{\emph{only}} as a post-calibration gauge input after UWB-only inter-anchor geometry recovery.
The ultrasound observations do not enter the self-calibration cost function; they act as a post-calibration spatial alignment constraint.

\subsection{Dataset Overview}

The dataset includes:
\begin{itemize}[nosep]
  \item 24~static UWB-Tag positions recorded with tag BSF66F and distributed across the anchor array footprint (edge, centre; low, mid, high elevations; multiple antenna facing directions).
        The static set is balanced over four tag-facing groups: each facing group contains 6~positions, with 3~edge and 3~centre positions and 2~low, 2~mid, and 2~high positions.
  \item 17~dynamic RotoArm captures: a rigid wand with two UWB tags (BS2DCE, BSDC91) rotating continuously at fixed angular speed. Across capture sessions, the RotoArm mounting angle was adjusted so that the rotation plane varied between horizontal and vertical orientations; the two tags also followed circular trajectories with different radii. The dynamic set is organised as a tilt-by-facing design, with approximately planar, low-tilt, mid-tilt, high-tilt, and near-vertical motion cases.
  \item Vicon Motion Capture System recordings of retroreflective markers on all 8~anchors and on the tag assemblies, providing sub-millimetre 3D ground-truth reference coordinates.
\end{itemize}

\subsection{Solver Nomenclature}
\label{sec:solver_nomenclature}

Throughout this report:
\begin{itemize}[nosep]
  \item \textbf{v1-old, v2, v3-full, v3-lite, v4-io}: AutoPos anchor self-calibration solver versions.
        v4-io denotes the joint robust least-squares solver that minimises inter-anchor range residuals
        using iteratively reweighted least squares with Huber loss,
        solved with a Trust Region Reflective (TRF) optimisation method.
        See \cref{app:layout} for full definitions.
  \item \textbf{T1\,--\,T4}: Pure-UWB tag localisation solver variants, all based on delay-corrected range residuals
        $r_i^{\mathrm{res}} = (\lVert\mathbf{x} - \mathbf{a}_i\rVert + d_{\mathrm{anchor},i} + d_{\mathrm{tag}}) - r_i^{\mathrm{meas}}$
        solved via Gauss--Newton iterations with Huber robust loss ($k=2.0$).
        The variants differ in weighting and temporal context:
        \textbf{T1}~uses per-anchor sigma and Huber weighting only (memory-free, i.e. no temporal history or prior);
        \textbf{T2}~adds a range-quality penalty derived from the DW1000 diagnostic fields;
        \textbf{T3}~further adds residual-history (EMA) weighting and a weak temporal prior to the previous position.
        \textbf{T4} (current production solver) applies adaptive branching:
        in full 8-anchor frames it uses the memory-free T1 path to avoid temporal-history bias;
        under anchor dropout it activates T3-like quality/residual-history weighting and the temporal prior.
        All outlier handling is \emph{soft down-weighting}, not hard link rejection.
        See \cref{app:tag} for full definitions.
  \item \textbf{F0\,--\,F5}: External position filters applied \emph{after} the tag solver on the solved 3D position stream.
        They do not re-process ranges, modify the anchor layout, or change delay calibration.
        F0 is a passthrough (all headline results use F0);
        F1--F3 are progressively more robust causal Kalman-style filters;
        F4 is a deployable fixed-lag smoother;
        F5 is an offline RTS smoother that serves as a diagnostic upper bound.
        See \cref{app:filter} for full definitions.
  \item The \emph{headline configuration} is \textbf{v4-io/T4/F0}: the v4-io anchor layout, current production tag solver, and unfiltered position output.
        All accuracy claims in this report refer to this unfiltered pipeline unless explicitly stated otherwise.
\end{itemize}

Complete mathematical definitions of all solver components are given in \cref{app:solvers}.

\section{Evaluation Methodology}
\label{sec:coord}
% ============================================================

\subsection{Ground-Truth Reference Frame}

The Vicon Motion Capture System provides the primary evaluation reference.
Anchor and tag ground truth use the same marker-holder construction.
Every DWM1001C-Dev module, anchor or tag, carries an identical
3D-printed cross-shaped marker holder with five asymmetrically placed
retro-reflective markers; in Nexus each holder is modelled as a rigid
body, and the exported antenna point is a model-defined virtual point
obtained by shifting the rigid-body pivot, located on the holder support
axis, along that axis by the caliper-measured offset to the UWB antenna
centre.
Because the module housings and the holder design are identical, the
marker arrangement, the pivot definition, and the pivot-to-antenna
offset are the same for all anchors and tags by construction.
The exported antenna positions and trajectories therefore already
include the pivot-to-antenna offset; no further extrinsic correction is
applied in the analysis.
The Vicon-derived 3D positions serve as ground truth throughout this report unless explicitly stated otherwise.

\subsection{Vicon System Evidence}
\label{sec:vicon_evidence}

The Vicon reference was recorded with 12 Vicon Vero v2.2 cameras in Nexus 2.16.
A single WandWave calibration was performed on the morning of the measurement and is embedded identically in all 50 capture files.
The per-camera calibration evidence gives a median image error of 0.085\,px, a median per-camera mean world error of 0.18\,mm, and a maximum per-camera mean world error of 0.42\,mm.

All TRC trajectory exports use \SI{120}{\hertz} in the \texttt{DataRate}, \texttt{CameraRate}, and \texttt{OrigDataRate} header fields.\footnote{The integer \texttt{MeasuredFrameRate} field in the \texttt{.system} files reads 121 for two RotoArm captures; this is integer rounding of the measured rate, and those captures are not outliers in the temporal-alignment analysis of \cref{sec:roto_temporal}, so no timebase correction is applied.}
The embedded Nexus processing settings have gap filling disabled.
Anchor markers have 0\% missing frames in all captures, while the R03 wand markers show 14--35\% missing frames from occlusion and were left unfilled.
The within-session marker standard deviation is sub-millimetre in the median (0.19\,mm), with a maximum of \SI{2.4}{\milli\metre} on anchors F/G, consistent with micro-sway of the \SI{30}{\centi\metre} carbon-fibre extensions.
Session-mean anchor positions are stable across the full measurement day to within \SI{1.5}{\milli\metre} for all anchors, excluding the anchor-G labelling anomaly described below.

The anchor ground-truth layout is computed from the first five static captures, ID01--ID05.
Within each capture, every anchor antenna point is reduced by a coordinate-wise median over all frames; the five per-capture medians are then combined by a second coordinate-wise median.
This single layout is used for all rigid registrations and range-bias diagnostics in this report.
Across all 24 static captures, the worst per-anchor session-mean deviation from this layout is at most \SI{1.5}{\milli\metre} when the anchor-G anomaly is excluded, the worst inter-anchor pair-distance perturbation is \SI{3.1}{\milli\metre}, corresponding to 2.6\% of the \SI{120.5}{\milli\metre} mean pairwise excess and 3.3\% of the \SI{94.6}{\milli\metre} mean per-anchor bias, and refitting the rigid registration with per-capture anchor means would move the 24 static truth positions by at most \SI{0.6}{\milli\metre}.
Anchor motion across the day is therefore negligible relative to all reported signals.
In capture R05, and in two unanalysed captures, the exported anchor-G antenna point jumps by approximately \SI{109}{\milli\metre} vertically due to a rigid-body marker-labelling error.
Because those affected per-capture anchor markers are never used by the analysis pipeline, and anchor truth comes only from ID01--ID05, this anomaly does not affect any reported result.

\subsection{Coordinate-Axis Convention}

The raw Vicon and intermediate analysis files use the laboratory export convention in which the vertical coordinate appears as the raw $Y$ axis and the horizontal plane is the raw $X$--$Z$ plane.
For consistency with the BioSpur/AutoPos convention used in the report, all tables and figures relabel the axes as $x/y$ horizontal and $z$ vertical:
\[
    x_{\mathrm{report}} = X_{\mathrm{raw}}, \qquad
    y_{\mathrm{report}} = Z_{\mathrm{raw}}, \qquad
    z_{\mathrm{report}} = Y_{\mathrm{raw}} .
\]
This is a fixed axis relabelling applied before reporting component-wise errors; it is not an additional fitted alignment and it does not change Euclidean 3D distances.
Thus entries labelled ``$x/y$ horizontal'' in the report correspond to the raw $X$--$Z$ horizontal-plane error, and entries labelled ``$z$ vertical'' correspond to the raw vertical $Y$-axis error.

\subsection{Spatial Alignment for AutoPos Anchor Layout}
\label{sec:coord_alignment}

The raw AutoPos anchor coordinates are internally self-consistent but live in an arbitrary 3D gauge: before comparison with Vicon, the whole layout may be translated, rotated, and mirrored without changing any inter-anchor UWB ranges.
Because the F/G/H ultrasound-height calibration in this dataset is treated as a deployment-gauge input rather than an independently validated Vicon reference (see \cref{sec:us_height}), the primary Vicon evaluation uses an anchor-locked rigid registration.
The rigid registration removes the arbitrary global coordinate frame while preserving the AutoPos layout shape and scale.
The mirror ambiguity inherent in range-only self-calibration is resolved by choosing the handedness with the lower anchor residual against Vicon.

The primary spatial transform is therefore
\[
    \hat{\mathbf{p}}_i = \mathbf{R}\mathbf{p}_i + \mathbf{t},
    \qquad
    \mathbf{R}^{T}\mathbf{R}=\mathbf{I},
\]
with $\det(\mathbf{R})=\pm 1$ to account for the range-only reflection ambiguity.
This is an orthogonal Procrustes registration with reflections permitted, which resolves the range-only mirror ambiguity during the anchor-only fit.
The fitted transform solves
\[
    \min_{\mathbf{R},\mathbf{t}} \sum_{i \in \{A,\ldots,H\}}
    \left\lVert
    \hat{\mathbf{p}}_i^{\mathrm{AutoPos}}
    -
    \mathbf{p}_i^{\mathrm{Vicon}}
    \right\rVert^2 .
\]
Only the 8 anchor positions are used to estimate this spatial transform.
Tag and RotoArm trajectories are \emph{never} used to fit the transform; the alignment is anchor-locked.
This procedure allows the unknown room-frame origin, orientation, and handedness to be removed, but it does not allow Vicon to scale-correct the deployed AutoPos layout.

For diagnostic purposes, a Sim(3) similarity alignment is also computed by adding one global scale factor to the rigid transform.
The Sim(3) residual is reported only to separate scale-related error from shape error.
It is not used as the primary absolute-accuracy claim, because a deployed AutoPos layout cannot rely on an externally supplied Vicon scale correction.
The corresponding v4-io diagnostic values are reported in \cref{tab:layout,fig:layout_scale}.

\subsection{Temporal Alignment for RotoArm Captures}
\label{sec:coord_temporal}

The static tag measurements are 120-second stationary sessions using tag BSF66F: each UWB position estimate is averaged over the session and compared with the corresponding Vicon static position.
They therefore do not require frame-level timestamp alignment.

The dynamic RotoArm measurements are more demanding because the Vicon and UWB systems were not hardware time-synchronised: no shared trigger pulse, GPIO event, or common UTC clock was recorded.
For each RotoArm capture, a single relative time offset $\beta$ is therefore estimated in post-processing.
The UWB sample times are shifted by $\beta$, the Vicon trajectory is linearly interpolated at the shifted UWB sample times, and $\beta$ is selected by minimising the median 3D trajectory residual over the overlapping circular-motion samples of the two wand-mounted tags.
This is a coarse-to-fine scalar search using the primary v4-io/T4 trajectory; the selected capture-level offset is then frozen and reused for all other layout, tag-solver, and IMU-replay comparisons.

This procedure uses the closest available post-processed offset for each capture, but it is still not equivalent to physical time synchronisation.
It corrects the unknown capture start-time offset, but it is not a hardware latency measurement and cannot remove residual timestamp jitter, clock drift, or ambiguity caused by the periodic circular motion.
Because $\beta$ is selected by minimising a trajectory residual, the remaining timing uncertainty can bias the reported dynamic error in either direction: imperfect alignment can inflate the error, while best-fit phase selection can reduce the reported error relative to an unfitted clock reference.
Consequently, RotoArm absolute trajectory errors should be interpreted as best-fit post-processed dynamic errors, not as purely clock-synchronised UWB dynamic errors.
The static-position results are not affected by this limitation.

\subsection{Ultrasound Height Reference}
\label{sec:us_height}

The deployed AutoPos system uses ultrasound-measured heights for anchors F, G, H.
This remains the intended deployable configuration: the layout is determined from UWB inter-anchor ranges and then assigned a physical vertical gauge using the US height inputs, not from Vicon coordinates.
However, the 28~May dataset does not support an independent US-height accuracy claim.
The H-anchor ultrasound measurement is suspected to be affected by the short \SI{20}{\centi\metre} carbon-fibre extension used during the measurement, which may have caused the sensor to range to an unintended local surface or support structure.
The F and G sensors used longer \SI{30}{\centi\metre} carbon-fibre extensions and show smaller height discrepancies against Vicon, whereas H shows the largest discrepancy.
For this reason, the ultrasound data are reported as a system component and deployment-gauge input, but not as a separate validated ground-truth source.
The primary numerical results in this report therefore use the anchor-locked rigid Vicon registration from \cref{sec:coord_alignment}.

\subsection{Evaluation Objects}

Throughout this report we distinguish two static-position quantities.
\textbf{Absolute accuracy} is the Euclidean 3D error between an estimated position and its Vicon ground-truth position (reported as median, P95, and RMSE); it is the Vicon-referenced error and reflects systematic bias plus random error.
\textbf{Repeatability} or \textbf{precision} (denoted $\sigma_{3D}$) is the 3D spatial spread of repeated UWB estimates at a fixed static position, computed relative to that position's own UWB cluster rather than relative to the Vicon coordinate.
It is therefore an internal UWB stability metric, not a Vicon absolute-error metric.
The two are independent: post-processing can improve repeatability without changing absolute accuracy.

For RotoArm data the tag is continuously moving, so the static repeatability definition does not apply.
The dynamic section therefore reports two different quantities: UWB trajectory error against Vicon truth, and RotoArm geometric self-consistency metrics such as radius-difference RMS and turn-centre repeatability.
The self-consistency metrics can be computed from either the Vicon trajectory or the UWB trajectory using the same circle-fitting procedure; they are useful physical-consistency checks, but they are not substitutes for Vicon-referenced dynamic accuracy.

\vspace{0.4em}
Both the static and RotoArm UWB recordings were designed for an approximately 10~Hz capture rate for each UWB tag.
\begin{itemize}[topsep=4pt,itemsep=4pt]
\item \textbf{Anchor layout:} 8 anchor positions, compared primarily via anchor-locked rigid Vicon registration; Sim(3) scale fitting is diagnostic only.
  \item \textbf{Static tag positions:} 24 positions recorded with tag BSF66F, each recorded as one 120-second static session ($\sim$1201 frames).
        Per-position accuracy is the Euclidean 3D error between the session-averaged UWB tag coordinate and the Vicon truth position.
  \item \textbf{RotoArm UWB-Tag trajectories:} 17 captures of continuous circular motion with tags BS2DCE and BSDC91.
        Per-sample 3D error is computed after temporal alignment (see \cref{sec:roto_temporal}).
\end{itemize}

The anchor-only residual is not the sole selection criterion for the end-to-end pipeline: v1-old has the lowest 3D RMSE in \cref{tab:layout}, whereas v4-io is the robust joint delay-layout solver used for the headline v4-io/T4/F0 localisation pipeline.
This distinction explains the report structure: v4-io is shown in detail, while all solver versions are reported under the same Vicon metric.

\subsection{Scale Bias Interpretation}

The diagnostic reduction from \SI{105.4}{\milli\metre} (rigid registration) to \SI{67.1}{\milli\metre} (Sim(3)), together with \cref{fig:layout_scale}, indicates that a substantial fraction of the absolute layout error is a coherent scale offset rather than random shape distortion.
\Cref{fig:layout_scale} makes this visible directly: 27 of 28 anchor-pair distances are longer in AutoPos than in Vicon, with a median pairwise scale error of approximately +4.1\%.
The fitted Sim(3) scale factor is 0.9583 in the AutoPos-to-Vicon direction, meaning that the diagnostic similarity fit contracts the AutoPos layout because its inter-anchor distances are systematically longer.
A corrected pairwise regression over the 28 anchor pairs gives a more careful interpretation.
An OLS model with intercept, $\Delta_{ij}=b_0+b_1 d_{ij}$, where $\Delta_{ij}$ is the AutoPos-minus-Vicon pair-distance excess and $d_{ij}$ is the Vicon distance, gives slope \SI{20.9}{\milli\metre\per\metre} with a 95\% confidence interval from \SI{-13.3}{\milli\metre\per\metre} to \SI{55.1}{\milli\metre\per\metre}.
This interval contains both zero and the pure-scale prediction of \SI{43.5}{\milli\metre\per\metre} implied by the 0.9583 Sim(3) scale factor, so distance dependence alone cannot discriminate a true scale distortion from a coherent per-link offset.
The fitted interval is also optimistic because the 28 pairs share per-anchor error terms.
The mean pairwise excess is \SI{120.5}{\milli\metre}.

The discriminating diagnostic is instead the per-anchor additive decomposition $\Delta_{ij}=\delta_i+\delta_j$.
This model reduces residual RMSE from \SI{63.7}{\milli\metre} for a constant-offset model to \SI{42.8}{\milli\metre}, and significantly improves the fit relative to the constant model ($F(7,20)=3.47$, $p\approx0.013$).
All eight endpoint terms are positive, and anchor~A has the largest term at \SI{145.6}{\milli\metre}.
The dominant layout error mode is therefore a coherent positive per-link range excess with per-anchor structure, which the Sim(3) fit expresses as an apparent +4.36\% scale.
It is not evidence of a true geometric scale distortion.
\Cref{sec:delay_decomposition} decomposes the underlying range-bias mechanism.


% ============================================================
\section{Delay--Layout Coupling}
\label{sec:delay}
% ============================================================

This section presents the clearest mechanism-level result of the measurement campaign.
It demonstrates that anchor geometry and residual delay/range-bias calibration are coupled quantities that cannot be separated naively.
The term ``delay correction'' in this section refers to the solver's fitted residual correction terms, not to a pure hardware antenna-delay measurement.
These residual corrections can absorb fixed antenna-delay mismatch, per-device range bias, and geometry-dependent error left after the nominal DW1000 antenna-delay setting.

A four-way ablation was performed by combining two layout sources (AutoPos v4-io self-calibrated coordinates, Vicon-measured coordinates) with different residual-correction treatments.
In \cref{tab:delay_coupling}, ``Vicon-measured anchor coordinates'' means that the UWB tag solver is given the anchor positions measured by Vicon instead of the anchor positions estimated by AutoPos from inter-anchor UWB ranging.
It does not refer to a different UWB-anchor hardware setup.

\subsection{Key Findings}

\begin{enumerate}[nosep]
  \item \textbf{No residual correction:} using Vicon-measured coordinates without residual correction yields \SI{311}{\milli\metre} RMSE---the worst of all four configurations.
        Ground-truth geometry alone is insufficient.
  \item \textbf{Transplanting AutoPos residual corrections} to the Vicon frame reduces the error to \SI{252}{\milli\metre}, but the corrections are conditioned on the AutoPos coordinate frame and do not transfer well.
  \item \textbf{Re-estimating residual corrections on the Vicon frame} gives the lowest RMSE in this ablation (\SI{78}{\milli\metre}), confirming that delay--geometry coupling is a major error source.
  \item \textbf{AutoPos self-calibration} achieves \SI{109}{\milli\metre} RMSE in this ablation---clearly above the \SI{78}{\milli\metre} of the re-estimated Vicon configuration, but obtained without any external measurement infrastructure.
        Its value is that it co-fits geometry and residual corrections in one self-consistent frame; it does not match an optically surveyed layout with frame-matched corrections.
\end{enumerate}

Prior UWB calibration work already shows that anchor coordinates and antenna-delay or range-bias parameters are accuracy-critical, and many systems estimate them jointly or with additional calibration infrastructure~\cite{shah2022node,piavanini2022self,nguyen2025coordinate}.
Some work treats hardware antenna delay as a separately calibrated, largely transferable quantity~\cite{shalaby2023calibration}, while robotics calibration work has shown that UWB sensor error models can be difficult to generalise across anchor setups and environments~\cite{lutz2019visual}.
The novelty here is not the existence of delay--geometry coupling, but the explicit four-way ablation in \cref{tab:delay_coupling} showing a concrete transfer failure: in the same physical deployment, Vicon-measured anchor coordinates degrade tag localisation unless the residual corrections are re-estimated in the Vicon coordinate frame.
To our knowledge, this is the first explicit four-way ablation demonstrating that externally measured optical ground-truth anchor coordinates cannot be substituted for a self-calibrated UWB layout without re-estimating residual delay/range-bias corrections in the same coordinate frame.

This result has direct implications for UWB system design and for the interpretation of ground-truth validation: optical reference coordinates cannot simply be dropped into a UWB solver as a ``better layout'' without re-estimating the residual correction parameters.
The fitted residual corrections are frame-conditioned quantities.

\subsection{Per-Anchor Range-Bias Decomposition and Error-Budget Closure}
\label{sec:delay_decomposition}

The scale signature in \cref{sec:anchor} was audited by decomposing the same fused inter-anchor range matrix in the Vicon metric frame.
The direct oracle regression uses the 28 fused inter-anchor distances $\hat{d}_{ij}$ that feed the layout solver and solves
$\hat{d}_{ij}-d_{ij}^{\mathrm{Vicon}}=d_i+d_j$ for the eight per-anchor range-bias terms.
This system is identifiable without a gauge constraint because every pair is observed.
All eight fitted terms are positive, with mean \SI{94.6}{\milli\metre} per device, corresponding to approximately 20~DTU under the one-way convention 1~DTU $\approx \SI{4.69}{\milli\metre}$, i.e.\ on the order of 0.1\% of the hardcoded 16436~DTU antenna-delay setting.
Anchor~A is largest at \SI{148.2}{\milli\metre}.
As a cross-check, the layout-based additive term for anchor~A in \cref{sec:anchor} is \SI{145.6}{\milli\metre}, agreeing with the oracle estimate within \SI{2.6}{\milli\metre}.

The error budget closes arithmetically.
The oracle mean implies a raw per-link bias of $2\times\SI{94.62}{\milli\metre}=\SI{189.2}{\milli\metre}$.
The production v4-io fitted anchor delays sum to \SI{275.3}{\milli\metre}; on a complete eight-anchor graph, the corresponding per-link absorption is $\sum_i d_i/4=\SI{68.8}{\milli\metre}$.
The residual \SI{120.4}{\milli\metre} matches the measured mean pairwise excess of \SI{120.5}{\milli\metre} within \SI{0.11}{\milli\metre}.
Absorption is limited by three solver choices acting together: anchor~A is fixed as the delay reference ($d_A=0$), the fitted delays are bounded by $|d_i|\leq\SI{60}{\milli\metre}$ with anchors~C and~D saturating at the positive bound, and the $\left(d_i/\SI{20}{\milli\metre}\right)^2$ regulariser penalises the common positive offset.
The unabsorbed range bias is therefore pushed into the layout geometry and appears in the rigid evaluation as expansion.

A diagnostic re-parameterisation confirms that the mechanism is the common mode, not the numeric delay bound alone.
In this rerun the anchor delays are written as $d_i=c+e_i$ for all eight anchors, with a free common-mode term $c$ and regularised zero-mean differentials $e_i$.
The fitted common mode is \SI{112.0}{\milli\metre}.
Under this diagnostic layout, the AutoPos-to-Vicon Sim(3) scale moves from 0.9583 to 1.0098, and the rigid anchor RMSE improves from \SI{105.4}{\milli\metre} to \SI{63.0}{\milli\metre}.
The zero-mean differential terms remain compressed by the same \SI{20}{\milli\metre} regularisation scale, so per-anchor structure, most visibly anchor~A's excess, is still under-represented in the common-mode fit and reappears as anchor~A's position residual; this is consistent with anchor~A retaining the largest rigid-registration residual and with the rigid RMSE stopping near \SI{63}{\milli\metre} rather than lower.
The separation is not perfectly sharp: clamping $c=0$ raises the solver cost from 81.62 to 138.09, while five perturbed initialisations converge to the same common mode and the same Sim(3) scale to within numerical precision.
Thus the common-mode parameterisation recovers metric scale to about the one-percent level from these ranges alone, but sub-percent scale still needs an independent constraint or bench delay calibration.
A relaxed-bound rerun that retains the $d_A=0$ gauge and the same regularisation does not collapse the scale, confirming that the gauge and regulariser choices matter, not only the bound.

The tag side explains why this metric-corrected diagnostic layout is not adopted as the headline pipeline.
With tag delay left at zero, the static session-mean median degrades from \SI{72.7}{\milli\metre} on the production v4-io layout to \SI{109.5}{\milli\metre} on the common-mode diagnostic layout.
This does not invalidate the headline accuracy: it shows that the deployed end-to-end pipeline partially benefits from the expanded anchor layout compensating an uncorrected positive tag-device delay.
The compensation is partial rather than complete.
In the fixed-tag-delay sweep of \cref{fig:tag_delay_sweep_phase1d}, the exploratory in-sample optimum is near \SI{80}{\milli\metre} for the common-mode layout and near \SI{60}{\milli\metre}, not zero, for the production layout.
Per-frame joint estimation of $[x,y,z,d_{\mathrm{tag}}]$ restores the common-mode layout median to \SI{72.9}{\milli\metre}, but the tail degrades (P95 \SI{317.5}{\milli\metre}, RMSE \SI{146.8}{\milli\metre}) and the fitted per-session $d_{\mathrm{tag}}$ medians are unstable (median \SI{46.7}{\milli\metre}, IQR \SIrange{9.5}{63.1}{\milli\metre}).
The conditioning is the expected GPS-clock-bias analogue: a per-frame common range offset is nearly collinear with radial and vertical position components for parts of this anchor geometry.
Consequently, the sweep optima are diagnostic and in-sample, not corrected headline results; a deployable tag-side correction should be a one-time or window-level delay calibration rather than an unconstrained per-frame term.

The Vicon marker-to-antenna-centre registration uncertainty is too small to account for the effect.
Monte Carlo and worst-case perturbations of the eight Vicon anchor coordinates show that a \SI{5}{\milli\metre} radial common-mode registration shift changes the mean pairwise excess by at most $\pm\SI{6.5}{\milli\metre}$.
Independent isotropic perturbations average down across the 28 pairs, and vertical common-mode shifts leave pair distances unchanged.
This is a bounding check on the optical reference, not a competing explanation for the \SI{120.5}{\milli\metre} signal.

\section{Static UWB-Tag Evaluation}
\label{sec:static}

Static performance is evaluated from two complementary viewpoints.
This section reports the unfiltered static baseline: \textbf{Vicon-referenced absolute accuracy}, which measures how far one session-averaged UWB tag coordinate is from the Vicon ground-truth coordinate, and \textbf{UWB-internal repeatability}, which measures the frame-to-frame spread of repeated UWB estimates during the same static sessions.

Static repeatability is not reported for the RotoArm data because repeatability requires repeated samples at the same stationary tag position.

\subsection{Temporal Alignment}

As defined in \cref{sec:coord_temporal}, the Vicon Motion Capture System and UWB system share \emph{no hardware time synchronisation}.
The RotoArm evaluation therefore uses one post-processed relative time offset per capture.
The median offset is \SI{45.5}{\second} (range \SIrange{37.7}{48.7}{\second}); this range reflects differing Vicon capture start times, not alignment instability.
The median alignment score is \SI{101.8}{\milli\metre}, consistent with the dynamic per-sample error floor of \cref{sec:roto_headline}.
The offset is frozen after this fit and reused across all layout/solver combinations.
The interpretive limitations of this post-processed timing alignment are discussed in \cref{sec:coord_temporal}.

\subsection{Negative Result: Vicon Anchors Do Not Solve Dynamic Error}

Even with Vicon-measured anchor coordinates and re-estimated residual corrections, the dynamic RotoArm error remains approximately \SI{106}{\milli\metre} median and \SI{200}{\milli\metre} P95.
This is a key negative finding: the $\sim$\SI{100}{\milli\metre}--\SI{200}{\milli\metre} dynamic error tail is \emph{not explained by anchor geometry alone}.

More plausible causes include:
dynamic range bias (Doppler-like effects on the UWB pulse),
antenna radiation pattern and orientation changes during rotation,
body/wand shadowing and antenna-orientation effects,
multipath from the rotating assembly,
and solver assumptions that do not account for motion state.

\section{Monte Carlo Keep-\texorpdfstring{$k$}{k} Robustness and Anchor Dropout}
\label{sec:mc}
\label{sec:keepk}
% ============================================================

This section separates two dropout models that are physically different.
The first model is a \emph{persistent anchor outage}: the same surviving anchor subset is used for the whole static session or RotoArm capture.
This is the deployment-relevant model for anchor failure or long-duration obstruction, and it carries the anchor-dropout robustness claim in this report.
The second model is an \emph{intermittent range-loss stress test}: the GPU replay draws a fresh keep-$k$ mask independently for each frame.
That per-frame mask model is useful for packet-level erasure stress, but it is not the same as a fixed missing-anchor set.

The primary metric is internal stability of the self-calibrated system under dropout, measured by static $\sigma_{3D}$ and by RotoArm turn-centre RMS.
The secondary metric is a Vicon-referenced sanity check: internal stability must not be read as absolute accuracy.
For that reason, the static replay also reports a frozen-registration Vicon column.
The frozen full-8 anchor registration matches the deployment semantics: the layout gauge is fixed during full-anchor calibration, and anchors are then removed only at runtime.
For $k<8$, the T4 keep-$k$ path also changes solver branch by activating quality/history weighting and a weak temporal prior, so the Vicon sanity column is not a pure anchor-count curve.

In the persistent-outage audit, all distinct fixed subsets are evaluated: 8 subsets for $k=7$, 28 for $k=6$, 56 for $k=5$, and 70 for $k=4$.
The intermittent stress replay uses 5\,000 per-frame random keep-mask repeats for each $k \in \{4,5,6,7\}$ and one full-anchor replay for $k=8$.
The RotoArm metric in this section is turn-centre geometric consistency, not Vicon-referenced absolute trajectory accuracy.

\section{Near-Wall Multipath Simulation}
\label{sec:wall}
% ============================================================

To contextualise the propagation environment's role in UWB accuracy under visually unobstructed conditions, a Monte Carlo propagation-risk simulation was conducted.
This simulation models the effect of nearby reflective walls and metallic objects on UWB ranging and self-calibration accuracy.
It is presented as discussion evidence, not as direct validation.

\subsection{Simulation Methodology}

The simulation is a first-order UWB propagation-risk study, not a replay of the complete AutoPos solver.
It uses an idealised paired-anchor layout with 8 anchors at the corners of a \SI{3}{\metre} by \SI{3}{\metre} horizontal footprint and two height layers separated by \SI{1.4}{\metre}.
Candidate tag positions are sampled on a \SI{25}{\centi\metre} grid inside the volume, giving 847 tag points.
For each tag point, ideal ranges to all 8 anchors are perturbed by a stochastic range-error model and then converted to position error using the local multilateration geometry matrix.
The reported P95 values are therefore distributional predictions over the simulated tag grid and noise trials; they should be read as propagation-risk evidence rather than direct validation.

The clear-path baseline uses zero-mean Gaussian range noise with \SI{3}{\centi\metre} standard deviation.
Wall cases add a positive range-bias component and extra variance that increase when either the tag or anchor is close to a wall and when the link is near-grazing to the wall surface.
The biased links also receive a positive-tailed random component to represent multipath-like range-error tails.
The wall-plus-metal scenario adds a coarse local-reflector model: six random metal/equipment boxes are placed near the layout boundary, based on photographs of the 28 May 2026 MaD Lab Erlangen test setup, and these boxes add additional proximity-dependent range bias and variance.
Side walls are modelled as reflective boundaries, not as path-blocking obstacles; true blocked-path propagation is not simulated.
The nominal ceiling height is \SI{2.5}{\metre}, but ceiling reflections are not included.

The study sweeps anchor-to-wall distance from \SI{0}{\centi\metre} to \SI{300}{\centi\metre} for a 4-wall room enclosure.
Three simulation scenarios are compared:
\begin{itemize}[nosep]
  \item Baseline wall scenario: default heavy reflective wall model.
  \item Wall-plus-metal scenario: the baseline wall model plus random metal/equipment boxes near the layout boundary, with their placement inspired by photographs of the 28 May 2026 MaD Lab Erlangen test setup.
  \item Material-sensitivity sweep: wall material sensitivity across light drywall, gypsum block, aerated concrete, sand-lime brick, and three reinforced-concrete grades (C25/30, C30/37, C40/50).
\end{itemize}
The baseline wall scenario and the material-sensitivity sweep use 128 range-noise trials per tag point; the wall-plus-metal scenario uses 96 range-noise trials per tag point and 12 independent metal-box seeds.

\subsection{Ground-Reflection Consistency Check}
\label{sec:ground_reflection_check}

The wall simulation above does not include floor reflection.
Because the static DOP audit in \cref{sec:dop_geometry} found the largest measured vertical-error median at the low tag height, a separate first-order consistency check was run on the real Erlangen Vicon geometry rather than on the idealised wall grid.
This check used the Vicon truth anchor coordinates and the 24 Vicon static tag positions.
For each anchor--tag link, the floor-reflected path was generated by mirroring the anchor across a swept floor plane $z_{\mathrm{floor}}$ in the raw Vicon vertical axis, with $z_{\mathrm{floor}}\in\{0,-100,-200,-300\}$\,mm.
The value $z_{\mathrm{floor}}=0$ follows the operator procedure that the Vicon origin was set at floor level, but it is not independently proven by the raw Vicon files; the sweep therefore keeps the floor-height uncertainty explicit.

The two-ray detector model was intentionally simple and was not tuned to the measured errors.
For direct length $L_d$ and reflected length $L_r$, the excess path is $\Delta L=L_r-L_d$.
Using the grazing-incidence convention for the vertically polarised WB003 antenna, the reflected coefficient was set to $\Gamma=-|\Gamma|$, with $|\Gamma|\in\{0.5,0.7,0.9\}$.
The effective range resolution $r_{\mathrm{res}}$ was swept over 15, 30, and 60\,cm.
The unresolved reflected path was modelled as a positive leading-edge range bias
\[
  b_{ij}=|\Gamma|\,r_{\mathrm{res}}
  \exp\!\left[-\left(\frac{\Delta L}{r_{\mathrm{res}}}\right)^2\right],
\]
which is largest when the direct and reflected paths are unresolved and tends to zero as the excess path becomes much larger than the effective range resolution.
The resulting per-link biases were propagated through the same local range-to-position linearisation used by the wall simulation.

\section{UWB + Synthetic IMU Fusion}
\label{sec:imu}
\label{sec:fusion}
% ============================================================

\textbf{Important caveat:} The results are based on \emph{offline replay/simulation} of the Erlangen UWB data with synthetic IMU fusion, not a closed-loop embedded measurement.
They are presented as simulation evidence for potential dynamic tail suppression under the assumed IMU sensor models, not as hardware-IMU validation.

\subsection{Simulation Methodology and Design}

The fusion study is an offline replay simulation.
The recorded RotoArm UWB data are replayed through the same computer-side analysis pipeline used for the dynamic UWB evaluation, while the IMU stream is generated synthetically.
No physical IMU was mounted on the tag during this Vicon test; therefore the results in this section are not hardware-IMU validation results.
The configuration IDs in this section follow the IMU-fusion codebook in \cref{app:imu_codebook}; for example, A0/U4/P4/L20/I5/T2 denotes the v4-io anchor layout, the old T4 pure-UWB solver renamed as U4, a UWB position post-filter P4, the L20 IMU model, IMU preprocessing I5, and the final PC-side fusion solver T2.

The synthetic IMU reference is derived from the Vicon marker reconstruction of the moving tag assembly.
For each RotoArm capture, four to five physical markers mounted on the UWB DWM1001C-Dev tag holder define one rigid body; one wand-B marker detached after the first dynamic capture.
There is no additional antenna marker in this conversion.
The Vicon rigid-body pivot obtained from the rigid-body reconstruction is shifted by the caliper-measured pivot-to-antenna offset to obtain the UWB antenna-centre trajectory.
The synthetic IMU is then simulated at this antenna-centre point.
This step matters because the UWB solver localises the antenna centre, not the arbitrary pivot or centroid of the Vicon marker set.
A separate rigid-body reconstruction sanity check gives residual medians of \SI{0.6}{\milli\metre} (P50-of-P50 across tracks) and \SI{1.5}{\milli\metre} (P50-of-P95), so the synthetic inertial prior is applied to the correct physical point, and these residuals are unaffected by the reduced marker count on wand B.

The Vicon-derived antenna-centre trajectory is first treated as a perfect motion source: no drift, no bias, and no sensor noise.
Nominal acceleration and angular-rate packets are then generated on the 120~Hz simulation grid from the reconstructed motion and the report frame convention.
The sensor model is applied afterwards.
For each L-series IMU row, the simulation injects datasheet-informed accelerometer and gyroscope noise, residual bias after static calibration, bias random walk, timestamp jitter, quantisation, vibration sensitivity, and IMU-to-body extrinsic residuals.
The raw datasheet offset is not used directly as drift, because a deployable system would perform at least a simple static bias calibration before fusion.

The central motivation for the BioSpur UWB+IMU architecture is the complementarity between global position and kinetic motion information.
The UWB trajectory provides the global, absolute-position information, but can contain outliers and short biased segments, while the IMU provides kinetic information that UWB alone cannot provide: short-term velocity, acceleration, and locally smooth motion.
Conversely, the IMU is not globally stable by itself because bias and drift accumulate over time.
Consequently, useful fusion is not a one-way ``IMU corrects UWB'' operation.
The IMU constrains the UWB trajectory by suppressing motion-inconsistent spikes, while UWB constrains the IMU by providing absolute position information that limits inertial drift and bias accumulation.
The full simulation sweep therefore includes several fusion families around this same principle.
Some rows use UWB positions to correct inertial drift, some use IMU relative motion to smooth or constrain UWB position jumps, some use bidirectional offline smoothing, and some tightly couple raw UWB ranges with IMU states.
Dedicated diagnostic rows also verify that the synthetic IMU stream itself is generated at the correct antenna-centre point before it is used as a motion prior.
The complete notation for these \texttt{U}-, \texttt{P}-, \texttt{I}-, and \texttt{T}-series variants is given in \cref{app:imu_codebook}.

At the algorithmic level, the common structure is a weighted trajectory-estimation problem.
Let $\mathbf{x}_k$ denote the local motion state at sample $k$ (position, velocity, and possible IMU bias states), let $\mathbf{z}^{\mathrm{UWB}}_k$ be the UWB-derived position observation, and let $\mathbf{u}^{\mathrm{IMU}}_k$ be the IMU increment or preintegrated motion constraint.
A generic UWB+IMU fusion objective can be written as
\begin{equation}
  \begin{aligned}
  \min_{\mathbf{x}_{1:N},\,\mathbf{b}_{1:N}}
  \quad
  &\sum_k
  \rho_{\mathrm{UWB}}
  \!\left(
    \left\lVert
      \mathbf{h}(\mathbf{x}_k) - \mathbf{z}^{\mathrm{UWB}}_k
    \right\rVert^2_{\mathbf{R}_k^{-1}}
  \right) \\
  &+
  \sum_{k=2}^{N}
  \rho_{\mathrm{IMU}}
  \!\left(
    \left\lVert
      \mathbf{x}_k -
      \mathbf{f}(\mathbf{x}_{k-1}, \mathbf{u}^{\mathrm{IMU}}_k, \mathbf{b}_{k-1})
    \right\rVert^2_{\mathbf{Q}_k^{-1}}
  \right) \\
  &+
  \sum_{k=2}^{N}
  \left\lVert \mathbf{b}_k - \mathbf{b}_{k-1} \right\rVert^2_{\mathbf{S}^{-1}} .
  \end{aligned}
\end{equation}
The first term is the UWB absolute-position constraint; it prevents the inertial solution from drifting away.
The second term is the IMU kinetic constraint; it penalises motion that is inconsistent with the short-term inertial measurement.
The third term models slow IMU bias evolution.
The robust losses $\rho_{\mathrm{UWB}}$ and $\rho_{\mathrm{IMU}}$ represent the gating or robust weighting used by the different solver families.

The configuration search then instantiates this principle in several ways.
The \texttt{P} code controls the UWB-side position smoothing before fusion; for example, \texttt{P4} is the fixed-lag smoother that gives the best production-row performance in this dataset.\footnote{The P-series post-filters in the fusion codebook are not identical to the main-text F-series filters. P4 is a session-window fixed-lag smoother with different parameters from F4, which is why A0/U4/P4 and T4+F4 have different metrics.}
The \texttt{I} code controls IMU-side preprocessing; the best rows use \texttt{I5}, which applies error-state preintegration after static bias handling.
The final \texttt{T} code is the PC-side trajectory solver.
It may be a position-domain prior, a loose-coupled EKF/UKF, a fixed-lag or bidirectional smoother, a tightly coupled raw-range solver, or an IMU-only diagnostic.
These solvers are also separated by the amount of temporal information they are allowed to use.
Capture-level solvers process one RotoArm capture at a time and are the relevant class for low-latency replay studies.
Session-level solvers, such as full-session RTS or batch smoothers, may use the whole recorded trajectory and are therefore offline upper-bound diagnostics rather than deployable real-time claims.
Therefore the \texttt{T} code should be read as an experiment setting, not as the scientific claim of this section.
The claim is the mutual constraint expressed in the objective above: UWB provides absolute position information that limits inertial drift, while IMU motion consistency suppresses UWB outliers and short biased segments.

The wider simulation sweep covers the available L-series IMU models, including perfect and control rows, low-cost stress rows, datasheet-backed consumer or drone-grade chips, and an industrial reference module.
The main report shows three representative sensors because they are the most interpretable design points:
\begin{itemize}[nosep]
  \item \textbf{L2} (MPU6050/JY61P-like): a low-cost consumer 6-axis IMU model and practical lower-bound candidate.
  \item \textbf{L16} (ICM-45686): a premium consumer/drone/robotics 6-axis chip candidate within the sub-100~EUR chip-class design space.
  \item \textbf{L20} (Xsens MTi-3): an industrial AHRS module simulated as accel+gyro only, used as a high-grade MEMS reference rather than a low-cost chip candidate.
\end{itemize}
Each selected sensor is evaluated over the same fusion-family configuration search: process noise, measurement noise, innovation gating, IMU preprocessing choice, and final trajectory solver are varied, with 5~random seeds per configuration.
All reported errors are evaluated against Vicon truth after the same dynamic alignment convention used in \cref{sec:coord_temporal}.

\subsection{IMU-Only Drift Diagnostic}

The fusion benefit is not only that the IMU smooths UWB position outliers.
The reverse constraint is also essential: without UWB absolute-position updates, the synthetic IMU trajectory drifts rapidly even after static bias handling.
\Cref{tab:imu_drift} reports the same diagnostic for the selected L2, L16, and L20 fusion rows.
The IMU-only prior is obtained by integrating the simulated IMU motion without UWB position updates; the constrained result uses the corresponding UWB+IMU fusion row.
This diagnostic confirms the intended two-way role of the BioSpur fusion architecture.
The IMU contributes short-term kinetic consistency, but it is not a stable global position source by itself.
UWB absolute positions are required to bound inertial drift; otherwise the IMU-only trajectory reaches metre-level position drift over the RotoArm captures.
The effect is visible for all three tested IMU tiers: L2 drifts the most, while L16 and L20 are better, but all three require UWB constraints to remain near the Vicon-referenced trajectory.
\Cref{fig:imu_drift_example} visualises the same point for a single track: without UWB updates the inertial prior preserves the circular motion pattern but its centre and scale drift away, whereas the UWB-constrained trajectory stays in the Vicon-aligned region.

\section{DOP Geometry Analysis}
\label{sec:dop_geometry}
% ============================================================

Dilution of Precision (DOP) was analysed to separate pure layout geometry from measured UWB error.
The calculation uses the full 8-anchor v4-io layout and a range-only Jacobian, i.e. each grid point is evaluated only from the anchor--tag line-of-sight unit vectors.
No measured range residuals, delay corrections, antenna effects, or Vicon tag errors enter this calculation.
The resulting GDOP, HDOP, and VDOP therefore answer a narrow question: whether the anchor geometry itself provides enough horizontal and vertical observability inside the measured volume.
They do not directly predict the final localisation error in millimetres.

Grid [mm] & Points & VDOP median & VDOP P95 & GDOP median & HDOP median \\

The main result is that the full Erlangen 8-anchor geometry is not vertically ill-conditioned.
Both grid resolutions give VDOP below 1.0 at the 95th percentile, and the median GDOP is close to 1.17.
This is consistent with the physical setup: the anchors form two height layers and cover the measurement region from multiple horizontal directions.
Thus, the vertical error observed in the static and dynamic experiments should not be attributed simply to a missing vertical geometric degree of freedom.
Two clarifications apply when comparing \cref{tab:dop_grid_summary} with the measured errors.
First, HDOP aggregates two horizontal axes while VDOP is a single axis; the per-axis horizontal DOP is approximately $\mathrm{HDOP}/\sqrt{2}\approx0.61$, so even per axis the geometry does not predict the measured factor-of-two vertical dominance under unbiased range noise.
Second, DOP propagates zero-mean uncorrelated range noise only.
The measured data separate exactly along this line: the frame-to-frame repeatability in \cref{tab:static_repeatability_headline} is not vertically dominated, whereas the Vicon-referenced accuracy in \cref{tab:static_headline} is.
The vertical accuracy deficit is therefore attributable to systematic per-anchor range-bias/delay effects, which DOP does not model, rather than to a vertical observability deficit.

The same calculation was also evaluated directly at the 24 measured Vicon static-tag positions.
At those points, the v4-io layout gives medians of GDOP = 1.140, HDOP = 0.804, and VDOP = 0.808.
HDOP and VDOP are therefore effectively equal at the measured positions.
Using the Vicon-measured anchor layout instead of the aligned v4-io layout changes the three medians by less than 0.2\%, so this conclusion is not an artefact of the self-calibrated layout.
Across the 24 positions, Spearman correlation between per-session $\sigma_{3D}$ and GDOP is $\rho=-0.02$ ($p=0.92$), and correlation between vertical Vicon-referenced error and VDOP is $\rho=-0.56$ ($p=0.005$).
The sign of the VDOP correlation is opposite to the simple noise-amplification prediction: lower VDOP is associated with larger measured vertical error.
A height-tier decomposition explains why.
Across the low, mid, and high static positions, the median VDOP values are 0.781, 0.902, and 0.808, while the corresponding median vertical errors are \SI{112.6}{\milli\metre}, \SI{33.3}{\milli\metre}, and \SI{62.6}{\milli\metre}.
The median internal $\sigma_{3D}$ values are \SI{65.8}{\milli\metre}, \SI{60.9}{\milli\metre}, and \SI{73.1}{\milli\metre}.
Thus, in the measured 24-point set, VDOP is partly a height proxy rather than a causal predictor of vertical error.
The low-height positions have better vertical geometry but larger vertical bias, which points to a height-dependent systematic effect rather than to weak vertical observability.
This motivated the ground-reflection consistency check in \cref{sec:ground_reflection_check}.
That check rules out the simple unresolved positive-delay two-ray floor model as the dominant measured mechanism because it fails the signed-residual and height-ordering tests.
The remaining height-dependent bias could still involve more complex floor interactions or antenna elevation-angle and phase-centre effects, but the present dataset is too small ($n=24$) to isolate those mechanisms by DOP alone.

The DOP fields are smooth and remain low over most of the tested region, while the condition number is less uniform and increases toward regions where the range Jacobian becomes less balanced.
This explains the value of DOP as a layout-quality diagnostic: it shows where the geometry is weak before any real ranging error is considered.
However, it also shows that DOP alone is not enough for this report.
The measured error includes effects that are absent from the DOP model, such as residual delay/range-bias calibration, antenna orientation, local propagation, and tag-facing direction.

\section{Limitations and Future Work}
\label{sec:limitations}
% ============================================================

\subsection{Measurement Limitations}
\label{sec:limitations_measurement}

\begin{enumerate}[nosep]
  \item \textbf{No hardware time synchronisation.}
        Vicon and UWB lack a shared clock.
        The per-capture time offset is estimated post hoc, so the reported dynamic error is a best-fit trajectory error rather than a hardware-synchronised error.
        Residual misalignment can inflate the error, while best-fit phase selection can also reduce the reported error relative to an unfitted clock reference.
        Future measurements should use GPIO-pulse or event-based hardware synchronisation.

  \item \textbf{Single measurement site.}
        All data comes from one lab environment in Erlangen.
        The propagation conditions (large open space, approximately \SI{1}{\metre} to the nearest wall, limited nearby metal clutter) are comparatively favourable.
        Performance in cluttered, obstructed, or multi-room environments may differ substantially.

  \item \textbf{Static tag positions are discrete.}
        Static accuracy was measured at 24 selected positions, not at every possible point in the measurement volume.
        The reported spatial trends are therefore representative, but they are not a dense error map.

  \item \textbf{RotoArm is a constrained dynamic scenario.}
        Continuous circular motion at fixed radius does not represent general 3D human motion.
        The BioSpur full-body tracking application will require validation with unconstrained movement trajectories.

  \item \textbf{IMU results are replay/simulation.}
        The IMU fusion evidence is based on offline replay with synthetic sensor models, not closed-loop embedded operation.
        Hardware-integrated IMU validation is required before claiming real-time fusion performance.

  \item \textbf{Marker--antenna alignment.}
        A systematic limitation of optically referenced UWB validation is the registration between the Vicon marker rigid body and the electrical reference point of the UWB antenna.
        Reported practice ranges from attaching a marker directly to the tag housing without explicit compensation~\cite{delamare2019,queralta2020}, to rigid-body mounts with a fixed lever-arm vector from the tracked body origin to the antenna reference point~\cite{cho2024,miluv2025,dumbgen2023}, to data-driven extrinsic calibration.
        This report follows the rigid-body approach: the tag holder is tracked by four to five reflective markers, the Vicon rigid-body pivot is reconstructed first, and a caliper-measured pivot-to-antenna offset is applied to obtain the antenna-centre trajectory.
        The identical holder construction is used on the anchor side, so the same few-millimetre mechanical registration floor applies to the anchor virtual points.
        Two residual floors remain.
        First, marker centroiding, holder tolerance, and manual offset measurement contribute a few millimetres of mechanical alignment uncertainty.
        Second, the antenna geometric centre is not exactly the RF phase centre; compact UWB phase centres can vary with incidence angle and frequency at the millimetre-to-centimetre level~\cite{pco2022}.
        The constant radial part of this offset is largely absorbed by delay/range-bias calibration, but angle-dependent phase-centre variation is not.
        Relative to the \SI{72.7}{\milli\metre} median static tag error reported here, this registration floor is small (on the order of 10\%), but it bounds the accuracy that this experimental design can support.
\end{enumerate}

\subsection{Identified Error Sources}

\begin{enumerate}[nosep]
  \item \textbf{Delay--layout coupling.}
        The +4.36\% global Sim(3) scale bias (median pairwise scale error +4.1\%; equivalently, a fitted AutoPos-to-Vicon scale factor of 0.9583 because AutoPos inter-anchor distances are longer) is the rigid-registration expression of a coherent positive inter-anchor range excess.
        The mean excess is \SI{120.5}{\milli\metre} per pair and is traced in \cref{sec:delay_decomposition} to per-device range bias: the oracle anchor-side estimate has mean \SI{94.6}{\milli\metre} per device, all eight terms are positive, and anchor~A is largest.
        Under the $d_A=0$ gauge, the \SI{60}{\milli\metre} delay bound, and the $\left(d_i/\SI{20}{\milli\metre}\right)^2$ regulariser, the production v4-io delay terms under-absorb this bias and the residual appears geometrically as apparent expansion.
        The ablation in \cref{sec:delay} shows that these terms must be interpreted together rather than as independent error sources.

  \item \textbf{Distance-dependent static error.}
        The static distance-to-centroid diagnostic in \cref{fig:static_distance} shows that peripheral tag positions tend to have larger errors.
        This is consistent with geometry becoming less favourable away from the array centre, but \cref{sec:dop_geometry} shows that DOP alone is not sufficient to explain the full static error distribution.

  \item \textbf{Dynamic error floor at $\sim$\SI{100}{\milli\metre}.}
        Neither layout improvement nor delay re-calibration reduces the dynamic median below $\sim$\SI{100}{\milli\metre}, pointing to UWB-intrinsic dynamic factors.

  \item \textbf{Dropout geometry risk.}
        The persistent-outage keep-$k$ analysis shows that the active anchor set matters, especially for vertical coverage.
        The per-frame mask replay is a separate intermittent range-loss stress test.
        Runtime confidence should depend on the active anchor set and on the loss mode, not only on the number of available anchors.
\end{enumerate}

\subsection{Next Steps}

\begin{enumerate}
  \item \textbf{Hardware time synchronisation.} Add a shared GPIO trigger
        pulse or event marker between the UWB logging host and the Vicon
        capture PC so that dynamic trajectory error can be reported as a
        clock-synchronised quantity instead of a best-fit post-processed
        offset. This directly removes the largest interpretive limitation
        of the RotoArm results (\cref{sec:limitations_measurement}).
  \item \textbf{Resolving the apparent scale bias / per-device delay calibration.}
        The audit traces the $+4.36\%$ apparent scale primarily to
        common-mode per-device range bias, an antenna-delay
        miscalibration class, rather than to a true geometric scale
        distortion. A re-parameterised solver with $d_i=c+e_i$ for all
        anchors and a free common mode recovers metric scale to within
        about 1\% from the UWB ranges alone, so the remaining
        scale--common-delay separation is weakly identified rather than
        exact. Remaining work is
        threefold: per-device antenna-delay bench calibration, or an
        independent metric constraint, for sub-percent accuracy;
        tag-side delay handling through one-time constant calibration or
        windowed estimation; and production validation of the solver
        re-parameterisation, including delay-gauge removal and
        bound/regulariser redesign, before adoption, because the
        corrected diagnostic layout currently degrades the end-to-end
        static headline when tag delay is left at zero.
  \item \textbf{DOP-aware runtime confidence.} Implement a runtime
        confidence estimate conditioned on the active anchor subset
        geometry (height-axis observability in particular), not only on
        the number of available anchors, as motivated by the stratified
        dropout result.
  \item \textbf{Hardware IMU integration.} Mount a physical IMU
        (ICM-45686 class, following the L16 simulation tier) on the tag
        and repeat the dynamic evaluation in closed loop. The
        synthetic-IMU replay results (\cref{sec:imu}) define the expected gain (tail suppression),
        but do not substitute for
        hardware-in-the-loop validation.
  \item \textbf{Unconstrained motion and additional environments.}
        Extend validation beyond fixed-radius circular motion to
        unconstrained 3D trajectories representative of rehabilitation
        movement, and repeat the measurement in at least one cluttered or
        multi-room environment to test the propagation-risk predictions
        of the near-wall simulation (\(\geq\)1\,m clearance guidance).
  \item \textbf{Ultrasound height-gauge verification.} Replace the 20\,cm
        H-anchor extension with the 30\,cm variant used on F and G,
        and validate the ultrasound height inputs against an independent
        reference so that the deployable US-gauge path can be evaluated
        as a ground-truth-supported claim rather than a gauge input only.
\end{enumerate}

\section{Conclusion}
\label{sec:conclusion}
% ============================================================

This report presented the first external ground-truth validation of the
AutoPos UWB anchor self-localisation system against a Vicon Motion
Capture System. All claims are dataset-bound to the 28~May~2026 Erlangen
measurement.

\textbf{Static localisation.} Under anchor-locked rigid registration,
the production v4-io/T4/F0 pipeline achieves 72.7\,mm median 3D error,
171.5\,mm P95, and 109.8\,mm RMSE over 24 static positions, with
37.4\,mm median horizontal error. The error budget is vertically dominated;
the DOP analysis shows this is not explained by geometric observability,
and the repeatability/accuracy split identifies it as systematic bias
consistent with residual delay/range-bias coupling.

\textbf{Anchor self-calibration.} The v4-io layout reproduces the Vicon
anchor geometry with 92.8\,mm median residual. The dominant layout error
mode is a coherent apparent $+4.36\%$ scale signature rather than random
shape distortion. The decomposition in \cref{sec:delay_decomposition}
traces this signature to common-mode per-device range bias that is
under-absorbed by the constrained production delay terms and therefore
expressed geometrically as expansion.

\textbf{Delay--layout coupling.} The four-way ablation showed that
Vicon-measured anchor coordinates \emph{degrade} tag localisation unless
the residual delay/range-bias corrections are re-estimated in the same
coordinate frame; with re-estimation they outperform the self-calibrated
configuration (78\,mm vs.\ 109\,mm RMSE in the ablation estimator). The
practical reading is twofold: fitted residual corrections are
frame-conditioned quantities that cannot be transplanted, and the value
of self-calibration lies in reaching comparable median accuracy without
external measurement infrastructure.

\textbf{Filtering is not calibration.} External position filters reduce
the static per-session spread from 67.1\,mm to 18.6\,mm without
materially changing Vicon-referenced absolute accuracy. For dynamic
data, only the latency-bearing fixed-lag and offline smoothers reduce
trajectory error.

\textbf{Dynamic error floor.} RotoArm trajectories show a
$\sim$100\,mm median dynamic error that persists across all layout and
solver combinations and is not removed by substituting Vicon-measured
anchor coordinates. The floor is also insensitive to the
tag-delay diagnostics, whose
median dynamic errors remain in the
approximately \SIrange{103}{107}{\milli\metre} range. The floor is
therefore attributed to UWB-intrinsic dynamic factors (antenna
orientation, motion-dependent range bias, shadowing) rather than to
layout quality, subject to the residual time-alignment uncertainty of the
non-synchronised setup.

\textbf{Robustness and fusion.} Persistent anchor outage degrades internal
stability as a function of both anchor count and surviving vertical coverage,
while intermittent per-frame loss creates an additional stress case. Offline
replay with synthetic IMU models indicates that UWB+IMU fusion acts
primarily as tail control, suppressing motion-inconsistent outliers
(track P95 reduced from 231.8\,mm to 112.1\,mm in the best production
row), while UWB absolute positions are required to bound inertial drift.

Within the measured envelope, the results support sub-decimetre median
static localisation from a fully self-calibrated UWB anchor array in a
favourable open-lab environment, and they identify the two concrete
obstacles on the path to clinical full-body motion capture: the apparent
scale bias, which the audit traces to per-device range bias and shows to
be largely recoverable by solver re-parameterisation, with per-device
delay calibration and tag-side delay handling as the concrete remaining
steps; and the dynamic error floor, which is addressed by the
synchronisation and IMU-integration steps above.
Neither is resolved by this dataset.

\section{Solver Component Definitions}
\label{app:solvers}
% ============================================================

This appendix provides the component definitions referenced throughout this report:
the anchor layout solver (V-series), the per-frame pure-UWB tag position solver (T-series in the main UWB sections), the external position filter (F-series), and the separate IMU-fusion experiment codebook used in \cref{sec:imu}.
The production pipeline is \textbf{v4-io/T4/F0}.

% ------------------------------------------------------------
\subsection{Anchor Layout Solvers (V1--V4-io)}
\label{app:layout}
% ------------------------------------------------------------

All layout solvers take directed inter-anchor UWB sweep ranges as input and output anchor coordinates $\mathbf{x}_i \in \mathbb{R}^3$ for $i \in \{A,\ldots,H\}$.
Some versions additionally estimate per-anchor residual delay corrections $d_i$.

\paragraph{Gauge convention.}
All layouts are computed in a relative coordinate frame with three gauge constraints:
anchor A at the origin, B on the positive $x$-axis, C in the $xy$-plane.
This removes the six rigid-body degrees of freedom (three translations, three rotations) inherent in distance-only observations.
The gauge does \emph{not} imply that A coincides with any external reference origin.

\paragraph{Pair range fusion.}
Before layout estimation, directed range measurements $r_{i \to j}$ and $r_{j \to i}$ are fused into a single symmetric distance estimate $\hat{d}_{ij}$ per anchor pair.
Three fusion methods are used:
\begin{align}
  \text{V1 (mean):} \quad & \hat{d}_{ij} = \operatorname{mean}(r_{i \to j} \cup r_{j \to i}) \\[3pt]
  \text{V2 (IVW):} \quad & \hat{d}_{ij} = \frac{\sigma_{ji}^2 \bar{r}_{ij} + \sigma_{ij}^2 \bar{r}_{ji}}{\sigma_{ij}^2 + \sigma_{ji}^2} \\[3pt]
  \text{V3 (MAD/MVUE):} \quad & \hat{d}_{ij} = \frac{\hat{\sigma}_{ji}^2 \tilde{r}_{ij} + \hat{\sigma}_{ij}^2 \tilde{r}_{ji}}{\hat{\sigma}_{ij}^2 + \hat{\sigma}_{ji}^2}
\end{align}
where $\bar{r}$ denotes the sample mean, $\tilde{r}$ the sample median, $\sigma^2$ the sample variance, and $\hat{\sigma} = 1.4826 \cdot \mathrm{MAD}$ the robust scale estimate.

\paragraph{V1-old: Classical MDS.}
Embeds the pair distance matrix into $\mathbb{R}^3$ via eigendecomposition of the double-centred squared-distance matrix.
No nonlinear refinement, no delay estimation ($d_i = 0\ \forall\,i$).

\paragraph{V2: MDS + regularised NLS.}
MDS initialisation followed by nonlinear least-squares refinement of
$\sum_{(i,j)} \bigl(\lVert\mathbf{x}_i - \mathbf{x}_j\rVert - \hat{d}_{ij}\bigr)^2$
with a weak vertical-spread regulariser ($\lambda \sum_i (z_i - \bar{z})^2$, $\lambda$ annealed over three passes).
No delay estimation ($d_i = 0$).

\paragraph{V3-lite: Robust fusion, no delay.}
Uses V3 MAD/MVUE pair fusion with MDS + NLS refinement.
Identical solver structure to V2 but with the robust pair distances.
No delay estimation ($d_i = 0$).

\paragraph{V3-full: Tukey IRLS with alternating delay.}
Alternates between:
\begin{enumerate}[nosep]
  \item \textbf{Coordinate update}: Tukey bisquare reweighted least squares on
    $r_{ij} = \lVert\mathbf{x}_i - \mathbf{x}_j\rVert + d_i + d_j - \hat{d}_{ij}$,
    with Tukey threshold $c = 4.685\,\hat{\sigma}$ and $\hat{\sigma} = \mathrm{MAD}(\{r_{ij}\})$.
  \item \textbf{Delay update}: For each anchor $i > 0$, $d_i \leftarrow \operatorname{median}_j\bigl(\hat{d}_{ij} - \lVert\mathbf{x}_i - \mathbf{x}_j\rVert - d_j\bigr)$.
\end{enumerate}
Iterated until convergence ($\Delta\mathbf{x} < 0.1$\,mm and $\Delta d < 0.05$\,mm) or 50 iterations. Anchor~A is the delay reference ($d_A = 0$).

\paragraph{V4-io: Joint Huber bounded-delay (production solver).}
Jointly estimates coordinates and delays by minimising:
\begin{equation}
  \min_{\mathbf{x},\,\mathbf{d}} \sum_{(i,j)} \rho_H\!\left(\frac{\lVert\mathbf{x}_i - \mathbf{x}_j\rVert + d_i + d_j - \hat{d}_{ij}}{15}\right)
  + \sum_{i>0} \left(\frac{d_i}{20}\right)^{\!2}
  + \Phi_{\mathrm{prior}}(\mathbf{x})
  \label{eq:v4io}
\end{equation}
where $\rho_H$ is the Huber loss with $f_{\mathrm{scale}} = 2.0$, delay is bounded $|d_i| \leq 60$\,mm, and $\Phi_{\mathrm{prior}}$ is a soft two-layer vertical prior:
\begin{itemize}[nosep]
  \item $d_D^{(z)}$ deviation from the lower-layer (A/B/C) median: $\sigma = 180$\,mm.
  \item E/F/G/H deviation from the upper-layer median: $\sigma = 220$\,mm.
  \item Layer gap bounded: $[450, 2600]$\,mm.
\end{itemize}
Solved via Trust Region Reflective (TRF) in \texttt{scipy.optimize.least\_squares}, initialised from V3-lite MDS+NLS.
Anchor~A is the delay reference ($d_A = 0$). Denominators (15, 20\,mm) set the relative weighting between range residuals and delay regularisation.
The $d_A=0$ delay gauge, the $\pm\SI{60}{\milli\metre}$ bound, and the $\left(d_i/\SI{20}{\milli\metre}\right)^2$ regulariser jointly limit how much per-device range bias the delay terms can absorb; the consequences are quantified in \cref{sec:delay_decomposition}.

% ------------------------------------------------------------
\subsection{Tag Position Solvers (T1--T4)}
\label{app:tag}
% ------------------------------------------------------------

All tag solvers are pure-UWB, single-frame, delay-corrected trilateration solvers.
Given anchor coordinates $\mathbf{a}_i$, ranges $r_i$, per-anchor residual delay $d_{\mathrm{anchor},i}$, and common tag delay $d_{\mathrm{tag}}$, each solver estimates the tag position $\mathbf{x}$ by iterative Gauss--Newton on the residual vector:
\begin{equation}
  e_i = \lVert\mathbf{x} - \mathbf{a}_i\rVert + d_{\mathrm{anchor},i} + d_{\mathrm{tag}} - r_i
  \label{eq:tag_residual}
\end{equation}

The effective per-range sigma is:
\begin{equation}
  \sigma_{\mathrm{eff},i} = \max\!\bigl(\sigma_{\mathrm{anchor},i},\; 5\bigr) \;\cdot\; \alpha_{\mathrm{quality},i} \;\cdot\; \alpha_{\mathrm{residual},i}
  \label{eq:sigma_eff}
\end{equation}

\paragraph{Quality penalty $\alpha_{\mathrm{quality}}$ (T2+).}
\begin{equation}
  \alpha_{\mathrm{quality},i} = \operatorname{clamp}\!\left(1 + 1.5 \left(\frac{100 - \bar{q}_i}{50}\right)^{\!2},\; 1,\; 4\right)
\end{equation}
where $\bar{q}_i$ is the average of instantaneous and EMA-smoothed DW1000 quality fields.
T1 sets $\alpha_{\mathrm{quality}} = 1$.

\paragraph{Residual-history penalty $\alpha_{\mathrm{residual}}$ (T3+).}
\begin{equation}
  \alpha_{\mathrm{residual},i} = \operatorname{clamp}\!\left(1 + 0.5 \cdot \frac{\max(0,\; \mathrm{EMA}_i - 120)}{80},\; 1,\; 2.5\right)
\end{equation}
where $\mathrm{EMA}_i$ is the exponentially weighted moving average of $|e_i|$ (decay $\alpha = 0.3$).
T1 and T2 set $\alpha_{\mathrm{residual}} = 1$.

\paragraph{Robust weighting.}
The normalised residual $\tilde{e}_i = e_i / \sigma_{\mathrm{eff},i}$ is reweighted with Huber loss ($k = 2.0$):
\begin{equation}
  w_i = \begin{cases} 1 & \text{if } |\tilde{e}_i| \leq 2 \\ 2 / |\tilde{e}_i| & \text{otherwise} \end{cases}
\end{equation}

\paragraph{Temporal prior (T3+).}
When a previous position $\mathbf{x}_{\mathrm{prev}}$ is available, the normal equations include:
\begin{equation}
  \mathbf{H} \mathrel{+}= \sigma_{\mathrm{prior}}^{-2}\,\mathbf{I}_3, \qquad
  \mathbf{g} \mathrel{+}= \sigma_{\mathrm{prior}}^{-1}\,(\mathbf{x} - \mathbf{x}_{\mathrm{prev}}) / \sigma_{\mathrm{prior}}
\end{equation}
with $\sigma_{\mathrm{prior}} = 180$\,mm. T1 and T2 do not use a temporal prior.

\paragraph{T4 adaptive branching.}
T4 applies context-dependent method selection per frame:
\begin{equation}
  \text{T4}(n) = \begin{cases}
    \text{T1 (memory-free)} & \text{if } n \geq 8 \\
    \text{T3 (quality + residual EMA + prior)} & \text{if } n < 8
  \end{cases}
\end{equation}
In full 8-anchor frames, T4 avoids temporal-history bias by using the stateless T1 path.
Under anchor dropout ($n < 8$), T4 activates quality weighting, residual-history weighting, and the temporal prior.

\paragraph{Solver parameters.}
All variants share: $\mathrm{max\_iters} = 8$, $\mathrm{max\_step} = 500$\,mm, $\mathrm{convergence} = 0.02$\,mm.
All outlier handling is \emph{soft down-weighting}; the C implementation does not execute a hard anchor-rejection loop.

\subsection{External Position Filters (F0--F5)}
\label{app:filter}
% ------------------------------------------------------------

These filters operate on the solved 3D position stream $\mathbf{z}_k = [x_k, y_k, z_k]^\top$ output by the tag solver.
They do not re-process UWB ranges, modify the anchor layout, or change delay calibration.

\paragraph{State and motion model (F1--F5).}
All Kalman-based filters use a 6-state constant-velocity model:
\begin{equation}
  \mathbf{x} = [p_x,\, p_y,\, p_z,\, v_x,\, v_y,\, v_z]^\top, \qquad
  \mathbf{F} = \begin{bmatrix} \mathbf{I}_3 & \Delta t\,\mathbf{I}_3 \\ \mathbf{0} & \mathbf{I}_3 \end{bmatrix}
\end{equation}
Process noise $\mathbf{Q}$ is parameterised by an acceleration standard deviation $\sigma_a$:
\begin{equation}
  \mathbf{Q}_{pp} = \tfrac{1}{4}\Delta t^4 \sigma_a^2 \mathbf{I}_3, \quad
  \mathbf{Q}_{pv} = \tfrac{1}{2}\Delta t^3 \sigma_a^2 \mathbf{I}_3, \quad
  \mathbf{Q}_{vv} = \Delta t^2 \sigma_a^2 \mathbf{I}_3
\end{equation}

\paragraph{F0: Passthrough.}
$\hat{\mathbf{p}}_k = \mathbf{z}_k$. No filtering. All headline results use F0.

\paragraph{F1: Causal constant-velocity Kalman filter.}
Standard predict--update cycle with fixed $\sigma_a$ and measurement noise $\mathbf{R} = \operatorname{diag}(\sigma_r^2, \sigma_r^2, (1.25\sigma_r)^2)$ where $\sigma_r$ is derived from the tag solver's residual RMS.

\paragraph{F2: Robust constant-velocity Kalman filter.}
Identical to F1 but with innovation gating: if the normalised innovation squared
$\mathrm{NIS} = \mathbf{y}^\top \mathbf{y}\, /\, \sigma_r^2 > 25$,
the measurement covariance is inflated $\mathbf{R} \leftarrow \mathbf{R} \cdot \min(30,\, \mathrm{NIS}/9)$.
This soft-rejects jump outliers without discarding the measurement entirely.

\paragraph{F3: Adaptive robust Kalman filter.}
As F2, with speed-adaptive process noise:
\begin{equation}
  \sigma_a = \begin{cases}
    \sigma_a^{\mathrm{high}} & \text{if } \lVert\mathbf{z}_k - \mathbf{z}_{k-1}\rVert / \Delta t > v_{\mathrm{threshold}} \\
    \sigma_a^{\mathrm{low}}  & \text{otherwise}
  \end{cases}
\end{equation}
Static context: $\sigma_a^{\mathrm{low}} = 300$, $\sigma_a^{\mathrm{high}} = 2000$, $v_{\mathrm{threshold}} = 500$\,mm/s.
Dynamic (ROTO) context: $\sigma_a^{\mathrm{low}} = 900$, $\sigma_a^{\mathrm{high}} = 3200$, $v_{\mathrm{threshold}} = 900$\,mm/s.

\paragraph{F4: Fixed-lag smoother.}
The fixed-lag smoother applies a bounded-window weighted average after F2/F3:
\begin{equation}
  \hat{\mathbf{p}}_k = \frac{\sum_{j=k-L}^{k+L} w_j \,\hat{\mathbf{p}}_j^{\mathrm{fwd}}}{\sum_{j=k-L}^{k+L} w_j}, \qquad
  w_j = \frac{1}{1 + |j - k|}
\end{equation}
with lag $L = 5$ (ROTO) or $L = 8$ (static). Deployable with a known output latency of $L / f_s$ seconds.

\paragraph{F5: Rauch--Tung--Striebel (RTS) offline smoother.}
Full-sequence forward Kalman filtering followed by a backward smoothing pass:
\begin{equation}
  \hat{\mathbf{x}}_k^s = \hat{\mathbf{x}}_k^f + \mathbf{C}_k \bigl(\hat{\mathbf{x}}_{k+1}^s - \hat{\mathbf{x}}_{k+1}^{-}\bigr), \qquad
  \mathbf{C}_k = \mathbf{P}_k^f \mathbf{F}_{k+1}^\top (\mathbf{P}_{k+1}^{-})^{-1}
\end{equation}
where superscripts $f$, $s$, $-$ denote filtered, smoothed, and predicted estimates.
F5 uses future samples and \emph{cannot} be deployed in real time.
It serves as a diagnostic upper bound on achievable accuracy for a given tag solver.
