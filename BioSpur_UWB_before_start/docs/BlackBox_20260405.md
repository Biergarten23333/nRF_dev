## Strict Preflight Redesign Applied

Date:
- 2026-04-05

Policy correction:
- Anchor USB is power-only for strict OTA.
- Strict launcher no longer uses Anchor USB serial logs, RTT logs, or direct debug reset as a hard preflight gate.

Code changes applied:
- `scripts/ota_single_shot_stable.py`
  - removed strict dependence on `anchor_lines > 0`
  - removed `OBS_UNAVAILABLE` as a failure mode caused only by missing forbidden-channel logs
  - strict preflight now relies on:
    - controller UART readiness
    - `device kind anchor`
    - UUID write/readback
    - reboot restore proof
    - `DFU SMP service ready`
- `scripts/build_anchor_ota_control_bundle.sh`
  - restored default strict anchor bundle to:
    - `prj.conf`
    - `prj_ota.conf`
  - no longer appends `prj_obs_rtt.conf` to the standard strict OTA build

Operational meaning:
- Anchor USB / J-Link observability remains available only as lab/debug tooling outside the strict OTA contract.
- Lack of Anchor-side USB logs is no longer treated as evidence that the target is unhealthy.
- `target_observability_available` remains in the launcher summary only as a legacy compatibility field.
- In strict mode it no longer means `anchor_lines > 0`.
- In strict mode it no longer means any Anchor-side USB/serial/RTT visibility.
- The strict decision should instead be read from:
  - `target_selection_ready`
  - `target_restore_ready`
  - `target_transport_ready`
  - and the controller log lines proving UUID latch / restore / `DFU SMP service ready`
