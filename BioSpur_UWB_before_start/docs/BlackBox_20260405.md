## 2026-04-05 OTA erase rc=6 root cause and fix

### Symptom
- Anchor A strict OTA deploy failed early with:
  - `OTA erase secondary slot request`
  - `OTA command done: group=0x0001 cmd=0x05 status=6 off=0`
  - `OTA erase failed: 6`

### Root cause
- This was not a timeout issue.
- In NCS 2.8 MCUmgr image-management, `rc=6` on image erase maps to `MGMT_ERR_EBADSTATE`.
- Zephyr image-management docs for image erase explicitly note that `MGMT_ERR_EBADSTATE` means:
  - the secondary image has been marked for next boot already and may not be erased.
- Our Anchor OTA profile did not allow erasing a pending secondary slot, so OTA aborted before upload.

### Repo fix
- Enabled:
  - `CONFIG_MCUMGR_GRP_IMG_ALLOW_ERASE_PENDING=y`
- File changed:
  - `apps/anchor/prj_ota.conf`
- Rebuilt:
  - `build-anchor-unified-ota-swline`
  - `build-master-control-anchor-ota-swline`
- Verified in built config:
  - `build-anchor-unified-ota-swline/anchor/zephyr/.config`
  - `CONFIG_MCUMGR_GRP_IMG_ALLOW_ERASE_PENDING=y`

### Current validation boundary
- Repo-side fix is complete.
- Reflashing the refreshed 52840 control image is currently blocked again by external J-Link/SWD attach instability on probe `683234364`.
- Therefore:
  - repo bug fixed
  - post-fix on-device OTA revalidation still pending hardware debugger recovery
