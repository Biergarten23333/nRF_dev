## Firmware / Control-Plane Changes

### 1. 52840 BLE master stale-connect watchdog

A watchdog was added in the BLE master connection path to recover from stale pending BLE connections.

Observed failure mode before this:

- scan found an anchor
- connect was queued
- `connecting_slot` stayed occupied
- no usable ready link appeared
- the sweep script looked stuck because the BLE control plane could not progress

Fix concept:

- record connect start time
- if a pending connection is not connected after a timeout, clear the peer and restart scanning

This prevents the master from staying permanently blocked on a stale pending BLE connection.

### 2. AUTOPOS role-switch timing reduction

The role-switch timing was reduced to avoid long conservative waits between master/matrix role changes.

Key timing intent:

- reduce sweep converge wait
- require fewer consecutive stable sweep lines before attaching
- reduce handoff delay before listening to the selected master
- reduce demoted-master settle time

This moves the system from a conservative debug workflow toward a faster production-style sweep workflow.

### 3. Commit ACK loss recovery

The most important fix was handling `COMMIT` acknowledgement loss.

Observed failure mode:

- 52840 sends `COMMIT` to an anchor
- anchor applies the new role
- BLE disconnects before the `OK COMMIT REBOOT_REQUIRED` notification is received
- 52840 sees `rc=-116`
- old logic marks role switch as failed even though the anchor already changed role successfully

The new logic does this:

1. Send `COMMIT`.
2. If `OK COMMIT REBOOT_REQUIRED` is received, continue normally.
3. If ACK is missing, reconnect to the same anchor.
4. Read anchor `STATE`.
5. If the expected role is already active with `cfg_valid=1` and `reboot_required=0`, accept the commit as successful.
6. Skip unnecessary reboot when the role is already active.

This is the key log pattern after the fix:

```text
AUTOPOS commit ack missing rc=-116; reconnecting to verify reboot_required
AUTOPOS commit already active after missed ACK: role=matrix
AUTOPOS anchor X commit already active role=matrix; skip reboot
AUTOPOS anchor X role verified
```

or for the promoted master:

```text
AUTOPOS commit ack missing rc=-116; reconnecting to verify reboot_required
AUTOPOS commit already active after missed ACK: role=master
AUTOPOS anchor X commit already active role=master; skip reboot
AUTOPOS anchor X role verified
AUTOPOS apply success: master=X
```


For this session, these warnings should not be treated as primary blockers because the environment was strong indoor NLOS/reflection.

Interpretation:

- Low quality does not necessarily mean anchor hardware failure.
- Multipath and NLOS can reduce quality in specific master/matrix pairings.
- The warnings are useful for later RF diagnosis, but not for judging whether the sweep control path is working.
- The current priority is role-switch stability and sweep duration.

## Current Bottleneck

The UWB sweep itself is fast. Once a master is active, collecting around 10 SW lines is almost immediate.

The remaining bottleneck is BLE control-plane role switching:

1. precheck period
2. demote previous master to matrix
3. promote next anchor to master
4. recover from missing COMMIT ACK
5. reconnect and verify state
6. attach sweep listener

Observed runtime:

```text
~46-50 s per round
~368-377 s for A-H, 10 sets
```

Therefore the performance problem is not the UWB ranging phase. It is the BLE role switching and verification path.

## Next Optimization Targets

### Priority 1: Reduce or remove per-round precheck

Current precheck still costs about 12 seconds per round. Across 8 rounds this is close to 96 seconds.

If the previous round completed successfully, the next round should be able to trust the staged state more aggressively and avoid a full conservative precheck.

### Priority 2: Faster commit recovery path

The system now correctly recovers from missing COMMIT ACKs, but recovery still costs time because it reconnects and reads state.

Possible improvement:

- If BLE disconnects immediately after COMMIT, treat this as expected for this firmware path.
- Reconnect with a shorter timeout.
- Read one state packet only.
- If role matches, continue immediately.

### Priority 3: Reduce duplicate verification

In successful incremental mode, only two anchors should need role work per round:

- previous master: `master -> matrix`
- new master: `matrix -> master`

Current logs show this is mostly true after the first round, but each role change still has multiple wait/verify/reconnect stages. These should be collapsed once the state machine is proven stable.

### Priority 4: Keep global reset optional

`anchor reset all autopos` is useful for controlled recovery, but it should not be mandatory for normal sweep startup. A global reset can add time and increase risk if the BLE control plane is already in a fragile state.

For now the recommended normal sweep path is:

```text
--no-bootstrap-autopos-reset
```

## Current Baseline

The current stable baseline is:

```text
A-H / 10 sets / all rounds successful / about 370 seconds
```

This baseline is stable enough for data collection, but not yet fast enough for the desired production workflow.

The next reasonable target is:

```text
A-H / 10 sets / below 120 seconds
```

To reach that target, the work should focus on BLE control-plane timing, not UWB ranging quality.
