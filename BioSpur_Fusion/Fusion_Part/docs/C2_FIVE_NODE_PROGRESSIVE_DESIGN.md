# 五节点 C2 渐进校准设计

设计日期：2026-09-13；实施更新：2026-09-15。状态：完整 C2 离线阶段联合求解已实现并完成一次全量运行；逐动作在线校准与最终跟踪精度尚未验收。目标是继承十节点的渐进更新机制，让五节点在整套 C2 中持续积累可复用的校准信息。进度显示必须由实际状态产生。本文不宣称渐进处理本身增加了传感器信息，也不把已有 smoke test 当作完整校准通过。

## 2026-09-15：整套离线 C2 联合求解入口

`c2_five_calibration/whole_session.py` 与 `tools/run_c2_five_whole_session.py` 实现全套数据上的阶段求解。它是完整 C2 的离线收敛流程，不冒充逐动作在线校准已经完成。每一阶段保留相同连续时间轴和全部实录 00、02–19；01 没有录制，不制造样本。删除任一动作或传入 H 都拒绝。

阶段依次为保留姿态观测下的全身初始化、有限观测残差下的联合姿态、共享航向及安装杆臂联合求解、原始 IMU 重放后的全套验证。固定航向对照采用相同步数；旧阶段只提供数值初值。几何尺寸、坐标和成熟关节模型沿用现有实现，安装旋转和零偏前端不另开重复自由度。共享优化当前更新航向与杆臂，不能称为所有安装参数已重新联合识别。

本轮补充：`session_heading.py` 将四个保留肢体的增量航向参数覆盖到 C2 首尾及每个正式动作中心。旧版本双臂末控制点停在 06/07 附近，余下约 15 分钟没有独立的时间支撑。新增节点只是数值参数位置，不是方向测量；既有原始方向因子保留，增量采用按真实时间间隔定义的有限变化率惩罚。该权重是工程设置，不是已测零偏协方差。H 当前保持 C2 末端增量，尚未实现 H 在线航向漂移跟踪。实际动作改善须以冻结后的回放另验。

传感器加速度约束始终在世界轴表达，差分的是各节点相对骨盆传感器的位置。腹前杆臂随骨盆旋转，其导数已进入方程；不需要再凭空添加一组旋转参考系惯性项。独立恒角速度合成测试验证了这一点，也验证忽略骨盆杆臂会产生误差。

依据：SIP 多帧姿态/加速度联合拟合、PIP 有限运动先验与物理求解、PNP 对旋转参考系和加速度语义的区分。不是这些论文的完整复现。人体约束合法和 C2 能量改善不等于 H 跟踪成功。

### 共享 Pelvis 加速度的相关性修正（实验开关）

`--shared-reference-metric` 将模型标记写入冻结几何配置，由 `acceleration_metric.py` 同时服务姿态目标和杆臂线性系统。四个相对加速度都减去同一 Pelvis，因此在等方差独立节点误差假设下，差值协方差为 σ²(I + 11ᵀ)，而不是 σ²I。白化保留四肢之间的差异，将共同分量缩小至 1/√5；其二次型等价于对五个原始残差消去共同平移加速度。更换被减参考节点不得改变该二次型。

该结构修正不代表已测得独立等方差噪声，也不声称解释了主要动作误差。0.75 m/s² 仍是原有工程尺度；不依据 H 或十节点差距挑选权重。旧冻结配置没有此标记时保留原度量，避免改变既有结果的可复现性。整套 C2 必须重算，并将新配置传入冻结 H 求解。

## 1. 目标与不变条件

输入仅为双前臂、双小腿及前腹部 pelvis 的五个六轴 IMU、原始采样时间、佩戴约定、实际动作说明及实测身体尺寸。节点为 BSFEC35、BSFB165、BSF6C53、BSF8BC4、BSFC2CC。算法可以复用十节点实现，不能消费移除节点的观测、拟合参数、姿态答案或对照误差来更新五节点。

使用全部实录 C2：00、02–19，共 19 个动作；01 未录制。按真实顺序包含准备、动作、过渡和间隙，不做 12/7 划分。06/07 各有两个正式阶段，03 有小圈/大圈阶段。阶段标签决定哪些条件适用，不能指定精确逐帧姿态。H 只在 C2 参数冻结后用于复现和下游检查。

用户期望的“进度条”：系统开始时保留未知，随着动作逐步形成稳定的安装与人体模型。后续动作能够纠正早期猜测；已掌握的信息不会因换动作而丢失；有冲突时明确显示尚未解决。完成动作与完成校准是两个状态。

## 2. 从十节点实际实现继承什么

当前代码中存在不同阶段的 progressive 实现，不能只凭目录名当作同一个已冻结算法：

| 已检查代码 | 实际机制 | 五节点处理 |
|---|---|---|
| `c2_coupled_progressive/estimator.py::refit_cumulative_calibration_tape` | 每个时间前缀使用此前保留的原始数据重估轴/中心，保持各段物理时间 | 继承前缀重估与原始证据保留语义；两端 IMU 因子需替换适配 |
| 同文件 `_replace_cumulative_calibration`、`solve_progressive_from_tape` | 全前缀估计替换旧线性化；只追加真正的新 heading 证据，避免重计旧数据 | 保留“替换重估结果，不重复加信息”的规则 |
| `v0/c2_progressive/pipeline_runtime.py` | 严格下一动作、事务式提交、快照及完整动作后冻结检查 | 借鉴事务和时间约束；不把整套历史十节点状态复制过来 |
| `v0/c2_basis/progressive.py::ProgressiveProfile` | 因子累计、使用之前状态初始化、前缀求解与快照 | 借鉴生命周期，不移植其九边未知量或全量人体参数 |
| `c2_five_calibration/calibration_prior.py` | 区分原始方向因子与条件姿态先验，同一证据禁止两处登记 | 扩展为跨整个渐进会话的证据台账 |

上述是源代码机制核对，不是对这些目录所有算法的科学验收，也未确认每个文件都属于用户最后一次冻结版本。实施前必须绑定采用的具体源文件版本，并对复用原语运行等价测试。

第一版优先用现有求解器加“逐前缀更新、状态保留、唯一证据台账”实现，不引入新的 GTSAM 依赖，也不重写通用非线性求解器。已有十节点的前缀重估足以作为可审计起点；若以后测得重算成本过高，再考虑成熟增量求解器。iSAM2 的因子增量与重线性化可作机制参考，不代表本方案已经集成或复现它。[官方文档](https://borglab.github.io/gtsam/isam2/)

QMT 的 `headingCorrection` 和铰链轴估计使用相邻两段的传感器输入。五节点缺少上臂、大腿、胸部 IMU，不能把估计出来的缺失姿态冒充第二个真实传感器，再声称得到独立观测。[QMT 官方接口](https://qmt.readthedocs.io/en/latest/python_functions.html#qmt.headingCorrection)

## 3. 一个会话，四类状态

### 3.1 共享安装与几何

每个保留节点的安装旋转、被支持的功能轴、传感器相对骨段的位置及其不确定性。实测体表尺寸及其内部几何映射单独持有；不得让 IMU 残差任意改变骨长。共享参数不会在每个动作重新初始化。

只在参数有支持时更新相应自由度。未得到可靠激励的杆臂或安装自由度保留不确定性，不用任意小方差制造完成。安装参数原则上整次佩戴恒定；如果证据显示 Tag 滑动，应报告一致性冲突，不能通过每动作一个安装矩阵掩盖。

人体约束先沿用经过核对的关节几何、运动范围和连续性机制，再适配缺失父段后的不确定性。不能把校准里观察到的最大抬臂/弯膝幅度当作该人的生理极限，也不再用四个统一弯曲增益代替个体校准。自由世界航向、未测头部等本来不属于交付的自由度，不应要求凭空确定后才允许进入下一阶段；哪些可观测参数组合是当前复现必需项，要在实现合同中明确。

### 3.2 随时间变化的状态

五个节点的连续导航状态、传感器偏置及相对航向变化，以及未测胸部/上臂/大腿等人体姿态。缺失姿态需要作为带约束的隐变量参与，而非已知真值或任意逐帧自由补偿。

偏置只由一个 owner 管理：初版保留已有连续六轴前端的估计与不确定性，不同时在另一个优化器无约束重复拟合同一偏置。校准历史中的参数变化不是人体运动轨迹，不能按动作时刻阶跃施加到四元数上。

校准冻结后，安装/几何/选定模型固定；导航、偏置传播和姿态估计继续随时间运行。允许何种无标签航向更新必须在冻结合同中明确，不能把“参数冻结”等同于时变状态停止，也不能允许 H 对共享安装参数重新拟合。

### 3.3 参考系与方向候选

指定一个公共世界航向基准，通常由初始 pelvis 参考定义；没有磁力计或外部方向时，不宣称得到了绝对世界航向。

完整安装旋转、各节点初始相对航向和时变航向可能相互补偿。参数化必须消除重复的参考系自由度，保留其余交叉不确定性。不能对同一种旋转同时开两个可自由调节的 owner，再分别报告很精确的结果。

保留合理方向分支及各自权重。当前模拟半球判别依赖特定的站姿身体坐标定义，尚未验证真实自然弯肘/旋前旋后下的 MD 映射；因此初版真人不能直接照抄两个矩阵元素的符号作硬拒绝。只有在真实坐标语义核对后才能排除明显错误半球，其余先作软条件。

低权重分支可转为可恢复的归档状态。后续出现冲突时应能重新展开，而不是在 T-Pose 阶段永久删掉实际正确的分支。达到候选预算上限时标记“搜索不完整”，不能宣称唯一解。

### 3.4 唯一证据台账与快照

每条证据记录：节点、原始时间区间、字段与有效支持、动作/阶段、原始来源哈希、依赖证据 ID、相关组、最晚证据时刻、参数化版本及因子版本。

一个原始片段得到的 gyro 主轴、VQF 姿态和网络先验并非三份独立数据。初版可明确采用复合目标，但不能把三项 Hessian 相加就称为三倍独立统计信息。原始似然与派生摘要的替代关系、重叠窗口及先验贡献要可追踪。

同一因子重算时替换旧版本。若对全前缀重新拟合，初始物理先验只计一次，旧后验只作为数值初值，不能再作为额外似然与同一份历史数据重复相乘。

## 4. 每次进度更新实际做什么

```text
收到新的连续五节点片段
    ↓
核对时间与数据支持，保持导航状态
    ↓
用“此前已提交状态”检查新片段的预测与冲突
    ↓
登记新证据；只激活当前已有支持的动作条件
    ↓
更新共享参数和人体隐状态，必要时重算此前的相关因子
    ↓
检查跨动作一致性、方向分支和参数支持
    ↓
原子提交新快照 → 更新进度显示
```

大预测残差不是自动拒绝新证据的理由。新动作可能正好在纠正旧判断；先区分原始传感器故障、正常新激励、未建模身体联动和真实安装冲突。健康数据必须保留，即使当前模型解释不好。

快照包括当前估计、候选、未确定方向、冲突、输入游标及最晚依赖时间。动作内按计算预算分块更新，动作和 06/07 的 15 秒阶段边界是强制检查点；第一版不承诺 200 Hz 参数优化。数据采集继续保持原采样时间，优化未完成时显示“估计更新中”，不能把上一结果标成当前已提交结果。

更新采用 prepare/solve/validate/commit 事务。失败候选及其诊断保留，上一已提交状态不被破坏。已读取的数据和已完成估计分别记录；不能偷偷跳过失败动作继续宣称全部校准完成。

## 5. 不让未来答案提前进入进度条

当前 `c2_arm_joint_smoke.prepare` 强制先有 00/02/04/05/06/07，并从完整肘前后两阶段估轴，是 batch smoke。当前 `shared_fit._tape` 强制全 19 动作；已有全量 `C2_PRIOR` 和冻结 frontend 也不能用于生成早期“在线快照”。这些入口不能简单套循环改名 progressive。

每个产物带 `max_evidence_time`。在 04 的快照中，安装轴和网络输入变换最多能依赖到 04；尚未发生的 06/07 信息必须保持未知。已知将来有哪些动作属于协议元数据，不等于允许读取将来的传感器值。

某个安装参数在 07 后改变时，允许对已经到达的 00–07 原始数据重解释。若影响了导航或循环网络输入，就从有效检查点重播已到达的前缀，并生成新的当前版本。不得沿用旧校准特征产生的隐藏状态，也不得重播尚未到达的数据。

保存两种不同视图：

- 当时快照：到 04 时系统实际知道什么，永不回写。
- 当前回溯：到 07 后，系统如何重新解释此前的 04。

进度曲线只取前者。最终离线回看可以显示后者，但清楚标明使用了后续 C2 信息。连续滤波不按动作重置；版本变更后的受控前缀重播不应冒充原时刻的在线输出。

## 6. 各动作怎样推动状态

动作条件用于支持和交叉约束，不承诺每个动作必定减少不确定性。

| 动作 | 渐进贡献 | 仍需保留的未知或自然运动 |
|---|---|---|
| 00 | 建立五节点连续状态，低运动重力/偏置诊断、佩戴初始分支 | 初始弯肘、完整安装方向和绝对航向未知 |
| 02 | 左右展开提供方向候选支持，与佩戴约定核对 | 疲劳下沉、轻微弯肘，不强迫水平或直肘 |
| 03 前后两阶段 | 骨盆多方向与不同幅度的运动，检查 pelvis 相关参数在换向时的一致性 | 不是已知圆轨迹，没有精确骨盆中心或位置真值 |
| 04/05 | 侧向抬臂的方向与动态信息，检查 T-Pose 候选 | 胸部/肩部平衡调整，不能指定上臂角轨迹 |
| 06/07 前半 | 屈伸主要运动轴的候选信息 | 陀螺变化可能混有上臂和躯干运动 |
| 06/07 后半 | 纵向旋转与约 90°弯肘，联合核对两阶段及此前抬臂 | 不精确 90°，不假定上臂绝对固定；允许修正此前轴 |
| 08/09 | 抬大腿与小腿自然下垂的组合条件，检查髋膝运动分解 | 可扶杆、膝角变化、全身平衡联动 |
| 10/11 | 坐姿伸膝提供小腿方向和功能轴，回头检查 08/09 候选 | 无大腿 IMU，不能把大腿位置/方向当实测 |
| 12/13 | 前脚掌接触与提踵的接触模式候选和运动一致性检查 | 小腿 Tag 不静止；无脚部 IMU。初版只加条件支持/诊断，不硬设零速点 |
| 14 | 骨盆实测响应及四肢动态对前后联动的共同约束 | 躯干动作标签不等于 pelvis 纯已知俯仰轴 |
| 15 | 左右转动与回正过程，检查相对航向和身体转动的分解 | 允许脚步、骨盆和下身联动，不强制 heading 闭合 |
| 16 | 双侧腿链与骨盆的共同一致性，检验坐姿/单腿阶段的参数 | 深度不固定、脚步可调整，不设全程固定足 |
| 17 | 低运动及会话前后健康/一致性检查 | 不强迫姿势或航向等于 00；此时尚有 18/19，不能冻结 |
| 18/19 | 在站姿不同髋状态下的弯膝证据，更新/核对同一膝参数 | 可扶杆，不假定脚跟真正接触臀部 |
| 全部过渡 | 连续状态、时间约束与运动一致性；保持未贴标签数据 | 准备阶段不保证静止，不固定重复次数，不压缩缺失时间 |

既保留全部数据，也逐条定义动作条件，不以“已放进通用残差”代替利用动作。对尚未建立可靠似然的动作关系，明确标为条件先验或诊断，不能伪造新传感器观测。

## 7. 什么才算校准在进步

首先看共享参数在允许胸部/上臂/大腿变化后，还剩多少数据支持。可用已有 nuisance 信息分析方法消去人体隐状态的局部影响，检查剩余可辨识方向；同时检查不同初值、方向模式和身体联动扰动下的稳定性。消去操作必须处理参考系零空间，不能用奇异矩阵求逆制造精度。

分别报告数据贡献、动作先验贡献及多分支差异。条件 Hessian 小方差、优化收敛或更多重复帧，都不能单独把状态变成“可靠”。统计不确定性尚未用覆盖率测试校核时，显示工程支持等级，不显示“95%可信”等概率承诺。

每个参数组使用这些状态：未形成支持、存在候选、有数据支持、跨阶段稳定、存在冲突。稳定可以退回冲突，早期不确定也可以在后续阶段被解决。新信息量不保证单调；错误先验被纠正时不确定性可能增大。

校准画面应显示采集主进度及 pelvis、左臂、右臂、左腿、右腿的分项状态，并给一句具体原因，例如“左前臂纵向轴已有支持，安装方向仍有两个候选”。采集主条可用已到达动作/阶段占比；不把参数成熟度压成未经验证的单一百分比。采集 100% 后可能显示“校准检查中”或“右臂仍有冲突”，不自动显示成功。

| 更正早期猜测 | 给早期条件加入合理偏差，后续独立运动应能纠正；不能永久锁住第一次解 |
| 同一证据重播 | 重放同一数据 ID 或重复窗口，信息不增长；全前缀重估不能重复累计旧后验 |
| 分块与恢复 | 不同合法块大小、保存恢复与不中断执行，在同样截止时间获得等价状态与证据集 |
| 自然联动与 heading drift | 有躯干/上臂联动及缓慢导航漂移时，不把全部变化吸收成安装旋转；失败如实定位 |
| Tag 佩戴滑动 | 注入真实安装变化，应报告安装变化或校准冲突，不能用恒定安装参数或缓慢 heading 吸收突变 |
| 歧义与错误分段 | 无激励保留未知，宽方向分支保留；错误分段出现冲突而不是强行提高成熟度 |
| 同源相关性 | 重复加入 gyro 轴、姿态和同源网络信息，不能人为降低统计不确定性 |
| 前缀重算与最终 batch | 相同证据、权重、参考系、候选预算和求解精度下，比较各模式目标值、可观测参数组合与预测；不强求不可辨识原始参数数值全等 |
| 新动作冲突处理 | 模型预测差不能自动删掉健康数据；应保留证据并触发候选/模型检查 |
| 冻结与 H 防火墙 | 未完成 18/19、存在未解决关键冲突或搜索不足时，不能声称冻结成功；H 无权更新校准 |

术语上区分“封存参数”和“校准验收通过”：任意成功或失败候选均可不可变封存用于复核，已授权的诊断 H 也可读取已封存但未通过的候选，只能标为诊断。所谓不能自动冻结，是不能把它发布为通过校准的正式参数；不能因此丢失失败证据或阻止已授权的诊断工作。

第一层先测试时间/证据状态机和现有上肢条件机制；它仍不构成 raw6 完整恢复。下一层用匹配实际阶段的连续六轴合成数据，包括偏置、漂移、人体联动及缺失，检验从前端到最终参数。再进入真实 C2 上肢前缀和全 19 动作。每一级都保存负例，失败不以更大真人计算掩盖。

此前 3°/5° smoke 门只对应那组受控条件，不作为产品精度标准。新机制的参数恢复门、分块数值容差和不确定性覆盖标准在新的合成运行前冻结；不能看 H 后选择门限。最终 H 沿用既有工程比较口径，不把十节点当外部真值。

## 9. 实现边界与最小顺序

设计的新责任可放在 `c2_five_calibration/progressive/` 子包，避免继续扩大 `shared_fit.py`。具体文件名在实施时按相邻代码调整，责任边界如下：

1. **session/state/ledger**：唯一会话、输入游标、证据依赖、事务快照、冻结条件。先实现防未来泄漏和防重计测试。
2. **phase factors**：让已有阶段和功能轴代码接受当前前缀，支持半段尚未到齐，不再要求先读取全 C2。
3. **update/replay**：用原有数学原语更新当前前缀，保留候选；安装或偏置变化时统一处理前端/网络依赖版本。每次重算替换旧版本。
4. **readiness**：读取参数支持与冲突状态，不参与求解，不看十节点评分，不改变测量时间。
5. **review**：读取不可变快照生成进度轨迹、前后对照和最终动画，不能修姿态或回写参数。

第一版使用前缀保留与受控重估，不提前引入复杂的不可逆边缘化或新图优化框架。性能先在真实短前缀测量，再决定检查点频率和是否需要增量化。源数据引用只读，不复制完整 capture；输出遵守现有磁盘门和每个实验的有界预算。

## 10. 交付与当前结论

设计完成后应先实现一个可运行的上肢 progressive 原型：从 00 到 07 一步步送入数据，展示真实的状态变化和各分支演变，同时通过前缀泄漏、重复证据、保存恢复及更正早期猜测测试。它是完整 19 动作主线的首个机制阶段，不是把其他动作留作永久检查集。

随后接入全部 19 动作与连续过渡，在冻结后生成 H 同时刻三窗动画。校准内部一致与 H 动作重建准确是两项检查，前者通过不保证后者通过。progressive 可以组织和积累已有信息，无法凭状态机创造原本不存在的观测；五节点成功与否仍由受控恢复和真实冻结复现判断。

独立设计复核：同会话另一代理只读检查本文，判定 `GO_TO_IMPLEMENTATION_DESIGN`，确认参考系、未来信息隔离、证据去重、冲突处理、前缀一致性及冻结边界已覆盖；建议的 Tag 滑动负例已补入。该判定只允许进入实现验证，不是算法或产品通过。
